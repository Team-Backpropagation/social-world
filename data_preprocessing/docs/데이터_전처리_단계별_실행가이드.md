## Step 3. 성연령 테이블 6개월 합치기

**목표**: 월별로 쪼개진 파일 6개를 하나로 합치기. **성연령 테이블 하나만 먼저 합니다.**

**중요**: 통신 3종 테이블을 하나로 합치려 하지 마세요. 성연령 테이블에는 시간대 정보가 없고, 시간대 테이블에는 나이·성별 정보가 없습니다. 원래 조합이 불가능한 데이터라 억지로 붙이면 틀린 표가 됩니다. **3종은 끝까지 따로 갑니다.**

```python
import glob

def load_flow(pattern):
    """월별 파일들을 불러와 중복 제거 후 하나로 합치는 함수"""
    frames = []
    for path in sorted(glob.glob(f"DATA/{pattern}")):
        one = pd.read_csv(path, sep="|", encoding="utf-8-sig", dtype=str)
        before = len(one)
        one = one.drop_duplicates()          # ← Step 2의 중복 제거를 여기서 일괄 적용
        if before != len(one):
            print(f"  [중복제거] {path}: {before:,} → {len(one):,}")
        frames.append(one)
    return pd.concat(frames, ignore_index=True)

age = load_flow("flow_age_pop_*.csv")
print("성연령:", age.shape)
```

**정상 결과**
```
성연령: (596252, 16)
```
성연령 파일에는 중복이 없으므로 `[중복제거]` 메시지가 **한 줄도 안 나오는 게 정상**입니다.

**왜 파일마다 따로 안 하고 함수에 넣었나**: 12월만 특별 취급하면 코드를 다시 돌릴 때 빼먹습니다. 모든 파일에 똑같이 `drop_duplicates()`를 걸면 문제없는 파일은 아무 일도 안 일어나므로 안전합니다.

**다음 조건**: `(596252, 16)` 일치

## Step 4. 지역 구분 컬럼 만들기 (강남구 / 춘천시)

**목표**: 통신 데이터에는 "강남구", "춘천시"라는 글자가 없습니다. `BLOCK_CD` 앞 5자리로 지역을 알아냅니다.

**배경**: `BLOCK_CD`는 20자리 코드인데 앞 5자리가 `11230`이면 강남구, `32010`이면 춘천시입니다. 그 외 코드는 격자가 옆 시군구 경계에 걸친 칸입니다.

```python
REGION_MAP = {"11230": "강남구", "32010": "춘천시"}

age["region"] = age["BLOCK_CD"].str[:5].map(REGION_MAP)   # 앞 5자리 잘라 이름 붙이기

print("대상 외 비율: %.3f%%" % (age["region"].isna().mean() * 100))
print(age["region"].value_counts(dropna=False))
```

**정상 결과**: 대상 외 비율 **0.057%** (강남구·춘천시가 아닌 경계 셀). 5%, 10%처럼 크게 나오면 앞 5자리 자르기가 잘못된 것이니 멈추세요.

**그 다음 — 대상 지역만 남기기**

```python
before = len(age)
age = age[age["region"].notna()].copy()
print(f"성연령: {before:,} → {len(age):,} (제외 {before-len(age):,}행)")
```

**정상 결과**

제외한 행 수(337)를 **메모해두세요.** 보고서에 "경계 격자 N행을 제외했다"고 써야 하는 숫자입니다. (경계 셀 제외/포함은 팀 미확정 사항 — 일단 제외로 진행하고, 방침이 바뀌면 이 Step만 다시 돌리면 됩니다)

## Step 5. 숫자 변환하고 저장하기

**목표**: 문자로 읽어둔 유동인구 수치를 숫자로 바꾸고 `clean/`에 저장

## Step 6. 성연령을 코호트 단위로 바꾸기 (집계 먼저!)

**목표**: 가로로 넓은 표(남10대, 남20대, …, 여60대이상 = 12개 컬럼)를 → "지역 × 월 × 성별 × 연령대" 한 줄씩인 세로 표로 바꾸기

**⚠️ 순서가 중요합니다 — 집계를 먼저, 모양 변환을 나중에**


## Step 12. 분할기준 적용 — 기간에 이름표 붙이기

**목표**: 데이터를 쪼개지 말고, "이 행은 평소 파악용 / 이 행은 검증용"이라는 **이름표 컬럼만** 붙이기

**왜 쪼개지 않고 이름표인가**: 나중에 기간 경계를 바꿔 실험할 때 파일을 따로 저장해두면 Step 1부터 다시 돌려야 합니다. 이름표 방식이면 이 Step만 다시 돌리면 됩니다.

**2026-09-21 변경 — 2분할에서 3분할로**

기존에는 baseline과 eval 둘로만 나눴는데, baseline(7~10월)에 추석 연휴가, eval(11~12월)에
연말이 섞여 **양쪽 모두 오염된 상태**였습니다. 추석 당일 강남 결제는 평소의 44%까지 떨어집니다.
그래서 이벤트 구간을 따로 분리했습니다. event 구간은 버리는 게 아니라 **이벤트 반응도를 측정하는
대상**입니다(가설 H-A의 재료).

```python
import numpy as np

BASELINE_END = "2025-10-31"
EVENT_PERIODS = [                     # 공휴일 달력 + 자동 탐지 결과
    ("2025-07-16", "2025-07-17"),     # 전국 동시 감소 (원인 미확인)
    ("2025-08-15", "2025-08-15"),     # 광복절
    ("2025-10-03", "2025-10-09"),     # 추석 연휴 (10/6 추석, 10/8 대체, 10/9 한글날)
    ("2025-12-24", "2025-12-31"),     # 연말 (12/25 성탄절 포함)
]

is_event = np.zeros(len(card_cohort), dtype=bool)
for start, end in EVENT_PERIODS:
    is_event |= card_cohort["date"].between(start, end).to_numpy()

card_cohort["split"] = np.where(
    is_event, "event",
    np.where(card_cohort["date"].le(BASELINE_END), "baseline", "eval"))

print(card_cohort.groupby("split")["date"].agg(["min", "max", "nunique"]))
```

**정상 결과**
```
                min        max  nunique
split
baseline 2025-07-01 2025-10-31      113
event    2025-07-16 2025-12-31       18
eval     2025-11-01 2025-12-23       53
```
113 + 18 + 53 = 184일. 이벤트 18일을 빼서 baseline이 123→113일, eval이 61→53일로 줄어든 것이
정상입니다.

이벤트 구간을 어떻게 찾았는지는 `notebooks/02_이벤트날짜_탐지.py` 와 `데이터_분석근거_정리.md` 12절을
보세요. 요약하면 **공휴일은 달력에서 직접 가져오고**(자동 탐지는 지역 간 상쇄로 절반을 놓침),
**탐지는 달력에 없는 이벤트를 찾는 보조 수단**으로만 썼습니다.

**절대 하면 안 되는 것**: `train_test_split(card_cohort, test_size=0.2)` 처럼 **무작위로 섞어서 나누는 것.** 시간 순서가 있는 데이터에서 이렇게 하면 12월 정보로 8월을 판단하게 되어(미래 정보 유입) 성능이 실제보다 좋게 나오는 반칙이 됩니다. 발표 때 심사위원이 지적하기 가장 쉬운 부분이기도 합니다.

**지역도 섞지 않습니다**: 강남구와 춘천시는 각각 따로 "평소 기준"을 계산합니다. 코드로는 `groupby`에 지역(`MCT_SGG_CD`)이 항상 들어가 있으면 됩니다.

**다음 조건**: baseline 113일 / event 18일 / eval 53일 확인

## Step 13-2. 업종 축 집계 (2026-09-18 추가)

**목표**: 업종(`MCT_RY_CD`) 축을 유지한 표를 별도로 만들기

위 5개 표에는 **업종 축이 없습니다.** Step 11의 코호트 집계에서 업종을 합쳐버렸기 때문입니다.
그런데 설계 노트의 지표 후보 중 "업종 다양성(소비처가 편의점 위주로 좁아지는지)",
"병의원·약국 결제 비중 급감" 같은 것은 업종 축이 있어야 만들 수 있습니다.

`run_pipeline.py`는 이 작업을 5단계에서 자동으로 수행합니다.

```python
industry = (card
    .groupby(["MCT_SGG_CD", "date", "MCT_RY_CD", "SEX_CCD", "AGE_CCD"], as_index=False)
    .agg(amount=("TS_AT", "sum"), cnt=("USE_CNT", "sum")))
industry["age_group"] = industry["AGE_CCD"].map(to_flow_age)

# 월 집계 — 업종 다양성 지표는 일별보다 월별이 안정적
industry["STD_YM"] = industry["date"].dt.strftime("%Y%m")
industry_monthly = (industry
    .groupby(["MCT_SGG_CD","STD_YM","MCT_RY_CD","SEX_CCD","AGE_CCD","age_group"], as_index=False)
    .agg(amount=("amount","sum"), cnt=("cnt","sum")))
```

**정상 결과**
```
일별 : (371734, 8)     업종 90종
월별 : (16311, 8)
금액 합계: 30,151,084,828,052  (원본과 동일)
```

| 파일 | 내용 | 단위 | 행 수 |
|---|---|---|---:|
| `card_industry_daily.csv` | 업종 축 유지 (연령 9구간) | 일별 | 371,734 |
| `card_industry_monthly.csv` | 업종 축 월 집계 | 월별 | 16,311 |

**설계 판단 두 가지**

연령대는 **원본 9구간(10~90대)을 유지**했습니다. 고령 고립 분석에서 70/80/90대를 '60대이상'으로
묶으면 약국·병의원 결제 패턴의 차이가 사라지기 때문입니다. 통신과 비교할 때 쓸 6구간(`age_group`)은
파생 컬럼으로 함께 넣었습니다.

거주여부(`resident`)는 **제외**했습니다. 업종과 교차하면 행이 약 65만으로 늘고 셀이 과도하게
희소해집니다. 거주자/외지인 분석은 메인 코호트표로 충분합니다.

**업종 다양성은 월별 표로 계산하는 것을 권합니다.** 일별은 건수 10 미만인 희소 셀이 약 9%라
다양성 지표가 크게 흔들립니다.

**지표를 만들기 전에 팀이 정해야 할 것**

**(2026-09-23 갱신 — 일부 확정됐습니다)**

고정지출은 **제외로 확정**했습니다. `세금공과금`, `보험`, `통신요금(이동,시내전화)`, `LPG가스`
4종입니다(청년 기준 건수 3.31% / 금액 10.99%). 반대로 **병원·약국·학원·교육비는 유지**합니다 —
금액이 크고 정기적이어도 방문과 선택을 수반하며, 청년의 활동 수준을 나타내는 정보가 있습니다.

같은 조사에서 더 큰 문제를 발견했습니다. **가맹점 소재지가 사업자 본사 주소로 찍힙니다.**

결제가 "서울 강남구 가맹점"으로 들어온 것입니다. 합치면 **강남 청년 건수의 23.8%**입니다.

그래서 집합을 두 개로 나눠 관리합니다. 자세한 근거와 90종 전체 분류는

## Step 15. 요일인자 제거와 이탈 탐지 (2026-09-23 추가)

**목표**: 코호트별로 "평소와 다른 날"을 판정하고, 그 다름이 어떤 종류인지 가르기

### ① 요일을 먼저 빼낸다

금요일에 소비가 많고 일요일에 적은 건 당연합니다. 그대로 두면 **매주 일요일마다
이상 발생**이 뜨고 진짜 신호가 묻힙니다. baseline 구간에서 코호트별·요일별 배수를 구해
각 날짜를 자기 요일 배수로 나눕니다.

**정상 결과**

| | 보정 전 | 보정 후 |
|---|---|---|
| 일요일 평균 이상도 | −1.33 | **−0.12** |
| 요일별 편차 폭 | 2.09 | **0.40** |

### ② 기준선을 두 개 둔다 — 이게 핵심 설계

체중계로 생각하면 쉽습니다. 최근 한 달 평균과 비교하면 어제 과식한 1kg은 잡히지만,
석 달에 걸쳐 서서히 빠진 5kg은 기준선이 같이 내려가서 **안 보입니다.**
고립은 하루아침의 사건이 아니라 서서히 진행되는 위축이므로, 이동평균만 쓰면
찾으려는 것을 구조적으로 못 봅니다.

| 컬럼 | 기준선 | 잡아내는 것 |
|---|---|---|
| `z_acute_*` | 앞뒤 29일 중간값 | 하루~사흘짜리 충격(휴일, 사고) |
| `z_sustain_*` | baseline 전체 중간값 | **수준이 계속 내려앉은 것** ← 우리 목표 |

산포(MAD)는 **baseline 구간에서만** 잽니다. eval의 변동까지 섞으면 이상치가 스스로
기준을 넓혀 탐지가 무뎌집니다.

### ③ 줄어든 것의 종류를 가른다

추석 당일 춘천 청년을 보면 미용실 0.04배·병원 0.06배로 무너지는 동시에
오락실 **1.74배**·놀이동산 **3.35배**로 늘었습니다. 추석은 사람이 집에 틀어박힌 날이
아니라 **가게가 닫힌 날**이고, 사람들은 열려 있는 곳으로 갔습니다.

> **핵심 질문: 줄어들면서 어딘가는 늘었는가?**
> 늘었다 → 휴일·폐점 등 외부 요인. 안 늘었고 편의점만 남았다 → 사람이 확인할 후보.

| 분류 | 뜻 |
|---|---|
| `대체동반감소` | 줄었지만 다른 활동이 늘었다 → 외부 요인 |
| `위축후보` | 사회적 활동이 줄고 생존 소비만 남았다 → **확인 대상** |
| `전반감소` | 줄었지만 구성 변화가 뚜렷하지 않다 |
| `정상` | 경계선 안쪽 |

**장치가 고장난 것이 아닙니다.** 이벤트 구간 144일 중 41일을 잡았고 그중 31일을

500명이 완전히 고립되어도 결제 건수는 0.25%밖에 움직이지 않습니다.** 경계선이
"보통 흔들리는 폭의 3배"인데 0.25%는 근처에도 못 갑니다.
**한 명씩 볼 수 없는 데이터로 한 명의 고립을 찾을 수는 없습니다.**

자세한 해석과 제출물 문구 권고는 **부록 C**를 보세요.

# 부록 A. 업종 90종 분류 — 고정지출 제외안

> 산정 기준: **청년(20~30대) 코호트**의 건수·금액 비중 (전 연령이 아님)

### 1. 이 문서가 답하는 질문

업종 다양성 엔트로피로 "단조로운 생활 패턴"을 재려면, **본인의 활동 의사와 무관하게
매달 자동으로 찍히는 결제**는 빼야 한다. 고립된 사람도 보험료·세금·통신비는 나간다.
이런 결제가 섞이면 실제로는 단조로운 코호트의 다양성이 인위적으로 높게 나온다.

따라서 제외 기준은 "비싼 것"이나 "필수적인 것"이 아니라 다음 하나다.

> **외출·접촉·선택을 수반하지 않고 발생하는 정기·자동 결제인가.**

이 기준 때문에 병원·약국·학원·서점·헬스장은 **제외하지 않는다.** 금액이 크고 정기적이어도
방문과 선택을 수반하며, 청년의 활동 수준을 나타내는 정보가 있다. (팀 결정, 2026-09-23)

| 방문판매/다단계판매 | 0.01 | 정기배송 가능성. 규모가 작아 영향 미미 |
| 부동산중개 | 0.00 | 3,219건. 계약 시 일회성. 규모 무의미 |

### 4. 검증 — 제외안이 지표에 미치는 영향

청년 코호트 8개(지역2 × 성별2 × 연령2)에 대해 네 가지 시나리오로 엔트로피를 계산했다.

| 시나리오 | 잔여 업종 | H 평균 | 규모 상관(log N) |
|---|---|---|---|
| A. 원본 90종 | 90 | 2.714 | −0.241 |
| B. 고정지출만 제외 | 86 | 2.665 | −0.459 |
| C. 고정 + ZZ 제외 | 85 | 2.649 | −0.252 |
| D. 고정 + ZZ + 원격 제외 | 76 | 2.587 | −0.622 |

#### 발견 1 — 지역 순위가 뒤집힌다

9월 기준 유효 업종 수(exp H):

| 코호트 | A. 원본 | D. 원격 제외 |
|---|---|---|
| 춘천 여성 30대 | 19.55 | 18.50 |
| 춘천 남성 30대 | 15.65 | 14.73 |
| 춘천 여성 20대 | 14.94 | 13.91 |
| 강남 여성 20대 | 15.93 | 12.61 |
| 강남 여성 30대 | 16.83 | 11.99 |
| 강남 남성 20대 | 12.13 | 11.80 |
| 춘천 남성 20대 | 12.06 | 11.18 |
| 강남 남성 30대 | 13.08 | 11.12 |

원본에서는 강남과 춘천이 섞여 있는데, 원격 결제를 빼면 **춘천 청년이 강남 청년보다
일관되게 다양하다.** 강남의 높은 다양성은 온라인 소비 다양성이었다는 뜻이다.
오프라인 생활권만 보면 강남 청년이 더 단조롭다.

#### 발견 2 — 지역 간 수준 비교는 포기해야 한다

규모 상관이 제외를 할수록 커진다(−0.241 → −0.622). 다만 지역이 2개뿐이라
**규모와 지역이 완전히 교란**되어 분리할 수 없다. 이 상관은 제거해야 할 기계적
왜곡이 아니라 "강남은 크고 단조롭다"는 실체와 뒤섞인 것이다.

결론은 앞서 모수 문제에서 내린 것과 같다. **지역 간 엔트로피 수준을 비교하지 말고,
같은 코호트의 시간축 변화만 본다.**

#### 발견 3 — 월별 엔트로피는 변화 감지에 못 쓴다

코호트 내 월간 변동계수가 평균 **1.06%**다. 6개월 동안 거의 움직이지 않는다.
월 단위 엔트로피는 변화 신호가 아니라 **코호트의 구조적 특성**이다.

일별로 계산하면 변동계수가 **2.93%**로 약 3배가 된다. 변화 감지에 쓰려면
`card_industry_daily.csv`로 일별 산정이 필수다.

#### 발견 4 — 일별 엔트로피는 추석을 잡는다

일별 엔트로피에 MAD robust-z를 적용한 결과(코호트 평균):

| 날짜 | B. 고정지출만 제외 | D. 원격까지 제외 |
|---|---|---|
| 2025-10-06 추석 당일 | **−3.99** | −2.73 |
| 2025-10-07 추석 연휴 | −1.87 | **−3.26** |
| 2025-08-15 광복절 | −0.28 | −0.86 |
| 2025-12-25 성탄절 | +0.20 | −0.03 |
| 2025-12-31 연말 | +1.15 | +1.19 |

두 안 모두 추석에 다양성이 무너지는 것을 잡는다. 최대 편차는 강남 30대에서
z = −8 ~ −10 수준이다.

#### 발견 5 — D안을 쓰면 요일인자 제거가 선행 필수다

D안의 이상치 상위 목록에 2025-08-17, 11-02, 12-07이 올라온다. **모두 일요일이다.**
원격 결제를 빼면 남는 것이 순수 오프라인 소비라서 요일 주기가 강해진다.
D안 채택 시 요일인자를 먼저 제거하지 않으면 매주 일요일이 이상치로 잡힌다.

### 5. 권고

**엔트로피 계산에는 D안(고정 + ZZ + 원격 제외, 76종)을 쓴다.** 지역 활동의 다양성을
재는 것이 목적이므로, 본사 귀속 원격 결제를 남겨두면 지역 비교가 무의미해진다.
단 다음 두 가지를 함께 적용한다.

1. **요일인자를 먼저 제거한다** (발견 5).
2. **일별로 계산한다** (발견 3). 월별은 코호트 특성 프로파일용으로만 쓴다.

**규모 지표(건수, 금액)는 F 4종만 제외한 B안을 쓴다.** 원격 결제도 소비 활동의
일부이므로 규모에서 빼면 실제 경제활동을 과소평가한다. 즉 지표별로 다른 업종
집합을 쓴다 — 이건 혼동의 소지가 있으므로 컬럼명에 명시한다.

```
cnt_all           전체 건수 (90종)
cnt_ex_fixed      고정지출 제외 건수 (86종)  ← 규모 지표
H_offline         오프라인 엔트로피 (76종)   ← 다양성 지표
n_eff_offline     유효 업종 수 = exp(H_offline)
```

### 6. 남은 결정

1. **ZZ_나머지(건수 17.99%)를 엔트로피에서 뺄 것인가.** 위 권고는 제외 쪽이다.
   빼면 청년 건수의 18%가 계산에서 사라지고, 남기면 정체 불명의 덩어리가 하나의
   업종으로 취급되어 다양성을 과소평가한다. 둘 다 불완전하다.
2. **백화점·면세점·수입자동차를 원격 집합에 넣을 것인가.** 이 셋은 본사 귀속이 아니라
   춘천에 업종이 없어서 0건일 가능성이 높다. 넣으면 강남의 실제 오프라인 활동을 깎는다.
3. **유치원을 육아 코호트 식별에 쓸 것인가.** 쓰면 활용 가치가 있지만 자녀 유무를
   추정하는 것이므로 개인정보 해석 범위를 팀에서 정해야 한다.

### 구조

키는 **지역 × 날짜 × 성별 × 연령**이다. 2 × 184 × 2 × 2 = **1,472행**, 코호트 8개 × 184일.

카드 9구간 / 통신 6구간 중 20대·30대는 양쪽에 동일 라벨로 존재하므로 연령 구간을
뭉개지 않고 1:1로 맞물렸다. 연령 축 손실이 없다.

### 해상도 규칙 — 반드시 지킬 것

컬럼명에 해상도를 박아뒀다.

- **접미사 없음**: 일별 값. 일 단위 변동 분석에 쓸 수 있다.
- **`_monthly`**: 월 단위 값을 그 달의 모든 날짜에 복제한 것. **일별로 변하지 않는다.**
  이걸 일별 변동 분석에 넣으면 조용히 틀린 결과가 나온다.
- **`region_` 접두사**: 연령·성별 구분이 없는 지역 단위 값. 같은 지역·같은 달이면
  네 코호트가 전부 같은 값을 가진다. 코호트 특성으로 해석하면 생태학적 오류다.

### 쓸 때 주의할 것

**지역 간 수준 비교를 하지 말 것.** 모수가 다르고(통신=체류 인구, 카드=결제 건수)

하나뿐이다. 이건 baseline/event/eval 분할과 MAD robust-z 구조와 정확히 맞는다.

**eval 구간의 감소를 그대로 고립 신호로 읽지 말 것.** baseline은 7~10월, eval은 11~12월이다.
계절이 다르다. 겨울에 외출이 주는 건 고립이 아니라 날씨다. 6개월치뿐이라 계절 보정을
할 방법이 없다. 기상 데이터를 외부 변수로 넣는 것이 부분적 대응이다.

**`chuncheon_term_flag`는 미검증이다.** 춘천 20대의 카드 건수가 7월 대비 9월에 남성 +21%,
여성 +30%로 뛰고 11월까지 유지되다 12월에 내려온다. 춘천 30대와 강남 네 코호트에는 이
패턴이 없고, 거주자(+19%)보다 외지인(+47%)에서 강하다. 대학 학사일정으로 추정하나
**춘천 소재 대학의 재학생 수와 학사일정을 확인하지 않았다.** 플래그만 붙여뒀고 보정에는
쓰지 않는다. 쓰려면 근거를 먼저 확보할 것.

**개인 단위로 해석하지 말 것.** 코호트 집계다. 강남 20대 여성이 20만 명이라면 그중
500명이 완전히 고립돼도 건수는 0.25% 움직인다. 이 데이터로 찾을 수 있는 것은
**집단 단위의 활동 위축**이지 고립된 개인이 아니다.

# 부록 C. 이탈 탐지 원리 — 쉬운 설명

> 통계를 몰라도 읽을 수 있게 썼습니다. Step 15가 무엇을 하는지 개념으로 이해하는 절입니다.
> 관련 파일: `data_preprocessing/src/detect_youth.py` · `clean/youth_signals_daily.csv`

### 한 줄 요약

평소와 다른 날을 찾는 장치를 만들었고, 그 장치는 잘 작동한다.
그런데 **찾으려던 고립 신호는 나오지 않았다.** 그게 왜 실패가 아닌지가 이 문서의 요점이다.

---

### 1. 우리가 하려는 일

8개 청년 집단(강남·춘천 × 남·여 × 20대·30대)의 184일치 소비를 놓고,
**"이 집단에 평소와 다른 일이 일어났는가"**를 매일 판정하는 장치를 만드는 것이다.

여기서 중요한 건 "평소"를 어떻게 정하느냐다. 평소를 잘못 잡으면 아무 날이나
이상하다고 소리를 지른다. 세 단계로 다듬었다.

---

### 2. 1단계 — 요일을 먼저 빼낸다

#### 왜 필요한가

금요일에 소비가 많고 일요일에 적은 건 당연하다. 이걸 그대로 두면
**매주 일요일마다 "이상 발생!"** 이 뜬다. 진짜 신호는 그 소음에 묻힌다.

식당 매출을 생각하면 쉽다. 월요일 매출이 토요일보다 적다고 "장사가 망했다"고
하지 않는다. 월요일은 원래 그렇다. 우리가 궁금한 건 **"이번 월요일이 평소 월요일보다
어떤가"**다.

#### 어떻게 했나

평상시 구간(7~10월)에서 집단별·요일별로 "이 요일은 평소의 몇 배인가"를 구했다.
그리고 모든 날짜를 자기 요일의 배수로 나눴다. 금요일 값은 금요일 배수로,
일요일 값은 일요일 배수로 나누는 식이다. 그러면 요일 때문에 생긴 높낮이가 사라진다.

배수 자체도 읽을 만하다.

| 집단 | 특징적인 요일 |
|---|---|
| 강남 여성 30대 | 일요일 **0.78배** — 여덟 집단 중 일요일이 가장 조용하다 |
| 춘천 남성 30대 | 토요일 **1.30배** — 주말에 가장 활발하다 |

같은 청년이라도 주말의 의미가 지역마다 다르다.

#### 결과

| | 보정 전 | 보정 후 |
|---|---|---|
| 일요일 평균 이상도 | **−1.33** | **−0.12** |
| 요일별 편차 폭 | 2.09 | **0.40** |

일요일이 더 이상 이상한 날로 잡히지 않는다. 소음이 빠졌다.

---

### 3. 2단계 — "평소와 얼마나 다른가"를 숫자로 만든다

#### 평균 대신 중간값을 쓰는 이유

한 반에 30명이 있는데 한 명이 로또에 당첨되면 **평균 재산**은 폭등한다.
하지만 **중간값**은 그대로다. 나머지 29명의 형편은 변한 게 없으니 중간값이 진실에 가깝다.

우리 데이터에도 추석 같은 극단적인 날이 있다. 평균으로 "평소"를 잡으면
그 며칠이 평소를 끌고 가버린다. 그래서 중간값을 쓴다.

"얼마나 흔들리는 게 정상인가"를 잴 때도 같은 이유로 **MAD**를 쓴다.
MAD는 "각 날이 중간값에서 얼마나 떨어져 있는지, 그 떨어진 정도의 중간값"이다.
말이 꼬이지만 뜻은 간단하다 — **보통은 이 정도씩 흔들린다**는 폭이다.

그래서 최종 점수는 이렇게 읽는다.

> **이상도 = (오늘 값 − 평소 값) ÷ 보통 흔들리는 폭**

−3이면 "보통 흔들리는 폭의 세 배만큼 아래로 벗어났다"는 뜻이다.
우리는 **±3을 경계선**으로 잡았다.

#### 흔들리는 폭은 평상시 구간에서만 잰다

11~12월(검증 구간)의 변동까지 섞어서 "보통 흔들리는 폭"을 재면,
이상한 날들이 스스로 기준을 넓혀버린다. 그러면 정작 이상한 날이
"이 정도는 보통"으로 판정된다. 그래서 폭은 평상시 구간에서만 잰다.

---

### 4. 기준선을 두 개 둔 이유

이게 이번 단계에서 가장 중요한 설계다.

체중 관리를 생각해보자. 오늘 체중을 어디에 비교하느냐에 따라 보이는 게 다르다.

- **최근 한 달 평균과 비교** → 어제 과식해서 1kg 늘어난 것은 잡힌다.
  그런데 석 달에 걸쳐 서서히 5kg 빠진 것은 **안 잡힌다.**
  기준선이 체중을 따라 같이 내려가기 때문이다.
- **작년 기준 체중과 비교** → 서서히 빠진 5kg이 그대로 보인다.

고립은 하루아침에 생기는 사건이 아니라 **서서히 진행되는 위축**이다.
최근 평균만 기준으로 쓰면, 우리가 찾으려는 것을 구조적으로 못 보게 된다.
그래서 두 가지를 다 계산했다.

| 이름 | 기준선 | 잡아내는 것 |
|---|---|---|
| `z_acute` (급성) | 앞뒤 29일의 중간값 | 하루~사흘짜리 충격 (휴일, 사고) |
| `z_sustain` (지속) | 평상시 구간 전체의 중간값 | **수준이 계속 내려앉은 것** |

우리 목표에 가까운 건 **지속** 쪽이다.

---

### 5. 3단계 — 줄어든 것에도 종류가 있다

#### 추석이 가르쳐준 것

추석 당일 춘천 청년의 업종별 소비를 평소와 비교했다.

**무너진 것**: 미용실 0.04배, 일반병원 0.06배, 종합병원 0.11배, 약국 0.33배
**늘어난 것**: 노래방 1.06배, 게임방·오락실 **1.74배**, 놀이동산 **3.35배**

읽어보면 답이 나온다. 추석은 **사람이 집에 틀어박힌 날이 아니다.**
병원과 미용실이 문을 닫았을 뿐이고, 사람들은 열려 있는 오락실과 놀이동산으로 갔다.
**밖에 나가 있었다.**

#### 그래서 판별 기준

고립의 모습은 이것과 정반대여야 한다. 가게는 열려 있는데 사람이 안 가는 것이고,
그러면 **줄어든 만큼 다른 데로 옮겨가는 흐름이 없어야** 한다.

> **핵심 질문: 줄어들면서 어딘가는 늘었는가?**
>
> - 늘었다 → 가게가 닫혔거나 휴일이다. **외부 요인.**
> - 안 늘었고 편의점만 남았다 → **사람이 확인할 후보.**

그래서 판정 결과를 네 가지로 나눴다.

| 분류 | 뜻 |
|---|---|
| **대체동반감소** | 줄었지만 다른 활동이 늘었다 → 휴일·폐점 등 외부 요인 |
| **위축후보** | 사회적 활동이 줄고 생존 소비만 남았다 → **사람이 확인할 것** |
| **전반감소** | 줄었지만 구성 변화가 뚜렷하지 않다 |
| **정상** | 경계선 안쪽 |

---

### 6. 내가 두 번 틀렸고, 두 번 다 고쳤다

솔직하게 적어둔다. 결과만 보고 넘어갔으면 잘못된 결론을 낼 뻔했다.

#### 오류 1 — 온라인으로 옮겨간 것을 고립으로 봤다

첫 실행에서 위축후보가 13건 나왔다. 반가워하기 전에 목록을 열어봤더니
**11건이 "온라인 결제 비중이 올랐다"는 이유로 잡힌 것**이었다. 날짜를 보니
추석 연휴와 연말. 강남에서 오프라인 가게가 닫히니 온라인으로 옮겨간 날들이었다.

생각해보면 당연하다. **고립된 사람도 온라인을 쓰지만, 휴일에 가게가 닫혀도 온라인을 쓴다.**
둘을 구분하지 못하니 판별 근거가 될 수 없다. 게다가 이 수치는 강남 14~31%,
춘천 0.0%로 지역 차이가 극단적이다(가맹점이 본사 주소로 찍히는 문제).

→ 판별에서 빼고 참고용 수치로만 남겼다.

#### 오류 2 — 소비가 늘어난 날을 "감소"로 판정했다

11월 10일 강남 여성 집단이 후보로 올라왔는데, 소비 규모 이상도가 **+2.49**였다.
소비가 평소보다 크게 늘어난 날이다. 업종 다양성만 좁아졌길래 잡힌 것인데,
이건 특정 업종에 몰린 쇼핑이지 위축이 아니다.

→ 다양성이 좁아져서 잡을 때는 "소비가 늘지 않았을 것"이라는 조건을 붙였다.

---

### 7. 결과 — 위축후보 0건

고친 장치로 다시 돌린 결과다.

| 구간 | 전체 | 이상 탐지 | 비율 |
|---|---|---|---|
| 평상시 (7~10월) | 904 | 11 | 1.2% |
| **이벤트 (공휴일 등)** | 144 | 41 | **28.5%** |
| 검증 (11~12월) | 424 | 7 | 1.7% |

**위축후보는 0건이다.** (급성 기준으로 2건 나오지만 둘 다 춘천 남성 30대의
평상시 구간이고 국지적 잡음으로 보인다.)

이 표는 두 가지를 동시에 말한다.

#### 좋은 소식 — 장치는 제대로 작동한다

이벤트 구간 144일 중 41일을 잡았고, 그중 31일을 `대체동반감소`로 분류했다.
추석 10/4~10/9, 광복절, 성탄절, 연말, 그리고 **원인을 모르던 7월 16~17일까지**
전부 걸렸다. 휴일을 위축후보로 잘못 분류한 건 하나도 없다.
평상시 오탐은 1~2%로 낮다.

장치가 달력을 스스로 다시 찾아냈다고 보면 된다.

#### 예상했던 소식 — 집계 데이터에서는 고립이 안 보인다

이건 처음부터 예상한 결과이고, 이제 실측으로 확인됐다.

강남 20대 여성 집단에 20만 명이 있다고 하자. 그중 **500명이 완전히 고립되어도
전체 결제 건수는 0.25%밖에 움직이지 않는다.** 우리 장치의 경계선은 "보통 흔들리는
폭의 3배"인데, 0.25%는 그 근처에도 못 간다.

**한 명 한 명을 볼 수 없는 데이터로는 한 명의 고립을 찾을 수 없다.** 당연한 일이
숫자로 확인된 것이다.

---

### 8. 그래서 우리 주장을 어떻게 써야 하나

**이렇게 쓰면 안 된다**

> "우리 에이전트가 고립 위험군을 탐지합니다"

지금 데이터로 뒷받침되지 않는다. 심사에서 근거를 요구받으면 댈 게 없다.

**이렇게 쓸 수 있다**

> "설명 가능한 이상은 자동으로 걸러내고, 설명되지 않는 것만 사람에게 올립니다"

1,472개의 집단-날짜 조합에서 이상 59건을 찾았고, 그 대부분이 달력으로 설명되며,
설명되지 않는 것은 0~2건이었다. 이건 **경보 피로 없는 모니터**라는,
실제로 방어 가능한 주장이다.

에이전트가 하는 일도 여기서 분명해진다. 매일 이상을 찾고, 휴일 달력과 구성 변화를
읽어서 **"이건 추석이라 당연하다" 대 "이건 설명되지 않는다"**를 가르고,
후자만 담당자에게 올리는 것. 규칙표를 돌리는 게 아니라 맥락을 읽는 판단이라
에이전트다운 역할이 된다.

---

### 9. 앞으로 필요한 것

집단 단위 집계만으로는 한계가 분명해졌다. 보완할 방향은 셋이다.

**더 좁은 단위로 내려가기.** 시군구 전체가 아니라 읍면동이나 격자 단위로 보면
같은 수의 고립이 더 크게 보인다. 다만 카드 데이터가 시군구까지만 있어서
통신 데이터 쪽에서만 가능하다.

**외부 데이터와 겹치기.** 1인가구 비율, 청년 복지 수급 현황, 고령화율 같은
공개 데이터와 겹쳐서 "원래 위험이 높은 지역"을 먼저 좁히고 그 안에서 신호를 보는 방식.

**계절 보정.** 평상시 구간이 7~10월이고 검증 구간이 11~12월이라 계절이 다르다.
겨울에 외출이 주는 건 고립이 아니라 날씨다. 6개월치뿐이라 보정할 방법이 없어서,
기상청 공개 데이터를 외부 변수로 넣는 것이 부분적 대응이다.
7월 16~17일 원인 미상 감소도 장마로 설명될 가능성이 있어 같이 해결된다.

---

### 10. 실행 방법

명령어는 이 문서 맨 위 **"이미 코드로 만들어져 있습니다"** 절에 있다. `python run_pipeline.py`
하나면 여기까지 전부 돌아가고, 이 부분만 다시 계산하려면 `--only youth`를 쓴다.

결과 파일은 `clean/` 안에 생긴다.

| 파일 | 내용 |
|---|---|
| `youth_master_daily.csv` | 청년 통합 마스터 (1,472행 × 31열) |
| `youth_signals_daily.csv` | 이상도 점수와 분류 (1,472행 × 37열) |

경계선 값(3.0)은 `src/detect_youth.py`의 `Z_THRESHOLD`에 있다.
2.5로 낮추면 위축후보가 2건 나오고 3.0 이상에서는 0건이라, 어디를 잡아도 결론은 같다.

### 읽을 때 조심할 것

**`위축후보`는 고립 판정이 아니다.** "평소와 다르고, 그 다름이 휴일로 설명되지 않는다"는
뜻일 뿐이다. 사람이 확인할 목록이지 결론이 아니다.

**집단 단위 결과를 개인 이야기로 옮기지 말 것.** "강남 20대 여성의 다양성이 낮다"가
"강남 20대 여성은 고립되어 있다"가 되면 틀린 말이다. 집단의 평균이지 개인의 상태가 아니다.

**지역끼리 수준을 비교하지 말 것.** 강남은 결제의 24%가 온라인이고 춘천은 0%다.
믿을 수 있는 건 **같은 집단이 자기 과거와 비교해서 어떤가**뿐이다.
