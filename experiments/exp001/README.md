# 개인 실험 EXP-001 — 첫 실행

**개인 실험 / 팀 미확정.** 2026-09-23 개선본 ZIP에서 웹·위험 분석 코드와 필요한 SQL만 복사했다. 기존 팀 폴더, 공식 문서, 원본 집계 데이터는 수정하지 않았다. 이 폴더에 운영 키나 원자료는 없다.

## 가장 짧은 실행 경로

이 폴더에서 터미널을 열고 실행한다.

```bash
python3 experiment.py check
python3 experiment.py all
```

`all`은 청년 8집단 합성 시험 6회 → 기존 집계 자료 읽기 전용 점검 → 웹 실행 순서다. 첫 실행에 웹 패키지가 없으면 `npm ci`를 시도한다. 화면은 `http://127.0.0.1:5173/preview`에서 볼 수 있다. 중지할 때는 터미널에서 `Ctrl+C`를 누른다. 네트워크나 분석 패키지 설치가 필요하면 `python3 experiment.py setup`을 한 번 실행한다. 빠른 연결 점검은 `python3 experiment.py risk --smoke`다.

| 명령 | 하는 일 | 저장·외부 연결 |
|---|---|---|
| `check` | 필요한 프로그램·환경변수 이름·SQL 파일 확인 | 없음. DB 접속 검증 아님 |
| `risk` | 가상 데이터 9,168행 생성, 48집단 사례 평가 | `risk_agent/experiment_outputs/`에만 저장 |
| `aggregate` | 개선본 ZIP의 기존 청년 집계 CSV를 읽고 입력·날짜 구간·상대 등급 점검 | 원본 수정 없음. 요약 JSON만 저장 |
| `web` | React 웹 실행 | `/preview`는 DB 저장 없음 |
| `all` | `check` → `risk` → `aggregate` → `web` | 테스트 DB 키 없으면 화면 미리보기만 가능 |
| `verify-db` | 테스트 계정 2개로 프로필·대화·미션 RLS 점검 | **격리된 테스트 Supabase에만 가상 행 생성** |

## 32×32 캐릭터 선택

`PixelCharacter.jsx`는 **32×32 논리 픽셀**로 플레이어와 정책·취업·심리 NPC를 그린다. CSS에서 64×64로 2배 표시한다. 플레이어는 방향 4개와 걸음 2프레임을 지원한다. 128×128 원본을 그리는 시간을 쓰지 않고도 광장에서 구별되는지 먼저 보는 선택이다. 모바일에서는 맵 높이와 직접 누르는 바로가기를 확보했다. 캐릭터는 독자적인 단순 도안이며 기존 게임의 자산을 복제하지 않았다.

`/preview`에서는 NPC 선택지 대화와 이동을 확인할 수 있지만, 대화 저장·미션·관리자 대응은 연결되지 않는다. `src/components/PixelCharacter.jsx`, `src/pages/Plaza.jsx`, `src/styles/global.css`의 `EXP-001` 주석에 크기와 동작 이유를 남겼다.

## 위험 탐지 시험

기간은 2025-07-01~2025-12-31(184일), 대상은 강남구·춘천시 × 남녀 × 20·30대의 8집단이다. 정상/거시 변화/미시 변화 3시나리오에 고정 난수 조건 2개를 적용한다. 실행 1회당 카드 일별 1,472행, 통신 월별 48행, 가상 대화 월별 8행이어서 **6회 총 9,168행**이다. 별도 출력 폴더에 입력·심은 패턴·판정을 남긴다.

2026-09-28 실행에서 심은 패턴 10개 중 9개가 Lv.3 이상, 주요 원인까지 맞은 것은 7개였다. 패턴을 심지 않은 38개 중 21개도 Lv.3 이상이었다. 이는 상대 5단계 등급이 정상 시나리오에서도 상위 집단을 만드는 문제를 드러낸다. **실제 개인의 사회적 고립 판별 정확도는 아니다.** 자세한 값은 `risk_agent/experiment_outputs/summary.json`과 `all_cases.csv`에서 확인한다.

기존 청년 집계 파일은 개선본 ZIP에서 **읽기만** 했다. 실제 입력은 8집단, 카드 일별 1,472행, 통신 월별 48행이고 날짜 구간 불일치는 0행이었다. 큰 거시 z값의 절댓값 최대는 1.502였지만 상대 등급 Lv.3 이상은 8집단 중 5개였다. 요약은 `aggregate_readonly_summary.json`에 있다.

## 실제 선택지·미션 DB 흐름 확인

이 단계에는 **별도 테스트 Supabase 프로젝트**가 필요하다. 팀 공유 프로젝트에서는 아래 절차를 실행하지 않는다.

1. 새 테스트 프로젝트를 만들고 SQL Editor에서 `database/01_socialworld_base.sql`, 이어서 `database/02_loop_schema.sql`을 적용한다.
2. Authentication에서 Anonymous Sign-Ins를 켠다.
3. `social_world/react_app/.env.example`을 같은 폴더의 `.env`로 복사해 **테스트 프로젝트의 URL과 anon key**를 넣는다. service-role/secret key는 웹 `.env`에 넣지 않는다.
4. `python3 experiment.py web` 실행 후 `/`에서 게스트 로그인 → 온보딩 → NPC 대화 → 미션 참여 → 완료 표시를 확인한다. 화면의 포인트는 가상 예시이며 실제 지급은 없다.
5. `.env`에 `EXP_ALLOW_DB_WRITES=isolated-test-project`를 추가한 뒤 `python3 experiment.py verify-db`를 실행하면 가상 사용자 A·B의 프로필·대화·미션 기록이 서로 보이지 않는지 확인한다. 이 명령은 테스트 계정 2개와 가상 행을 남기며, 위기 신고 RPC는 호출하지 않는다.

테스트 프로젝트의 URL과 anon key가 아직 없어 실제 DB 연결과 RLS 시험은 **미실행**이다. 환경 점검의 “키 입력됨”은 접속 성공을 뜻하지 않는다.

## 이번 구현의 경계

- 뒤에서 진행을 관리하는 **관리자 에이전트**, LLM 자유대화, 정책 API, 실제 보상 지급, 위기 사건의 사람 관리자 대응은 이번 코드에서 동작하지 않는다. 현재는 기존 3개 선택지 NPC와 코호트 추천 표시의 연결을 시험한다.
- 집단의 카드·통신 지표는 **개인 위험 단계가 아니다**. 사용자 화면에는 집단 위험 등급을 노출하지 않는다.
- 실제 위기 대응 프로토콜과 원문 저장 범위는 결정되지 않았다. 테스트에는 가상 사용자만 사용한다.
