# 사회적 고립 AI 에이전트 — 프로젝트 로드맵

2026-09-17

## 프로젝트 개요

2026 제14회 빅콘테스트 AI데이터활용 분야 「사회적 고립 예방 및 대응을 위한 AI 에이전트 개발」에 4인 팀으로 참가해, 통신(SKT)·카드(신한카드) 데이터로 강남구·춘천시의 사회적 고립 위험을 조기 탐지하고 복지자원을 추천하는 AI 에이전트를 설계해 10/21까지 1차 서류를 제출합니다.

오늘(9/17) 기준 마감(10/21)까지 34일이 남았고, 추석 연휴(9/24~26)와 한글날 연휴(10/9)가 끼어 있어 실질 작업일은 약 4.5주입니다. 팀은 이미 대회 데이터의 실제 컬럼 스펙을 확인하고 고립 정의를 브레인스토밍한 상태(데이터·지표 설계 노트)라, 이 로드맵은 곧바로 실행 단계로 들어갑니다.

역할은 팀장(PM, 전 영역 관여)과 팀원 1~3(포지션 미정, Phase 1에서 배정)으로 구성됩니다. 아래 Phase 표의 DE(데이터엔지니어링)·AN(분석/EDA)·ML(모델링)·AG(에이전트설계)는 특정 인물이 아니라 작업 영역 구분이며, 4명이 함께 진행하는 것을 전제로 합니다. 구체적 배정은 "역할 분담" 절 참고.

## 평가 기준과 로드맵 매핑

1차 서류 평가는 5개 항목(100점)으로 나뉘며, 로드맵의 각 Phase가 어떤 항목을 채우는지 아래와 같이 대응됩니다.

| 평가 항목 | 배점 | 채우는 Phase |
| --- | --- | --- |
| 아이디어 창의성·독창성 | 25 | Phase 1(고립 정의), Phase 3(위험지표) |
| 데이터 근거 및 분석력 | 25 | Phase 3(EDA), Phase 4(모델링) |
| 사회적 영향력 | 15 | Phase 4(에이전트 설계), Phase 5(보고서) |
| 실현 가능성 | 15 | Phase 4, Phase 5 |
| 데이터 지속 활용성 | 10 | Phase 4, Phase 6(체크리스트) |
| 완성도 | 10 | Phase 5, Phase 6 |

최소 요구 성과물 4가지도 함께 완성해야 합니다.

1. 핵심 인사이트 및 비즈니스 제안 — Phase 3~5
2. 데이터 분석 근거 자료(EDA, 지역·연령계층 비교) — Phase 3
3. 예측·분류 모델링 결과(성능평가, 재현 가능한 코드) — Phase 4
4. AI 에이전트 설계 결과(탐지·판단 로직, 복지자원 추천 체계) — Phase 4

## Phase 1 — 킥오프 및 기획 확정 (9/17~9/23)

이번 주의 목표는 "무엇을 어떤 단위로 볼지"를 팀 전원이 확정하는 것입니다. 데이터·지표 설계 노트에 남아있던 미해결 항목들을 이번 주 안에 결정합니다.

| 태스크 | 담당 | 완료 기준 |
| --- | --- | --- |
| 역할 분담 및 협업 툴 세팅(깃허브, 노션/슬랙) | 전원 | 저장소·채널 생성, 역할표 공유 |
| 고립 정의 2x2 매트릭스 축 2개 선택(자발성×지속기간 등) | AG | 매트릭스 1장, 4개 유형 정의 |
| 코호트 단위 확정(지역×연령대×성별) | AN | 코호트 스키마 문서화 |
| 격자-행정구역 매핑 테이블 제공 여부 대회 사무국 문의 | DE | 회신 확보 또는 자체 매핑 방안 결정 |
| 외부 공공데이터 소스 확정(KOSIS, 행안부, 고독사 통계 등) | AN | 소스 리스트 + 접근 방법 정리 |
| 대회 실데이터 신청/수령 상태 확인 | AG | 데이터 수령 완료 또는 신청 완료 |

체크포인트(9/23): 코호트 정의와 고립 정의 매트릭스가 확정되어 있어야 Phase 2로 넘어갈 수 있습니다.

## Phase 2 — 데이터 수집 및 전처리 (9/24~9/30, 추석 연휴 포함)

추석 연휴(9/24~26)가 이 주 초반과 겹치므로, 연휴 전(9/23까지)에 개인 작업으로 끝낼 수 있는 태스크를 몰아 배치하고, 연휴 이후(9/28~30)에 팀 협업이 필요한 작업을 진행합니다.

| --- | --- | --- |
| 대회 실데이터(통신·카드) 전처리 파이프라인 초안 작성 | DE | 연휴 전 |
| 외부 공공데이터(1인가구, 인구구조, 고독사 통계) 다운로드·정제 | AN | 연휴 전~중 (개인 작업) |

## Phase 3 — 탐색적 데이터 분석 및 위험지표 설계 (10/1~10/7)

통합 데이터셋 v0을 바탕으로 실제 패턴을 확인하고, 위험 신호로 쓸 지표 후보를 좁힙니다.

| 태스크 | 담당 | 완료 기준 |
| --- | --- | --- |
| 지역×연령대×성별 코호트별 유동인구·소비 패턴 비교분석 | AN | EDA 노트북, 주요 차트 5개 이상 |
| 강남구 vs 춘천시 1인가구·연령구조 가설 검증(청년 1인가구 비중 등) | AN | 가설 채택/기각 결론 |
| 위험지표 후보 리스트 확정(통신=배경지표, 카드=일별 트리거) | AN, ML | 지표 정의서(변수명, 산출식, 데이터 소스) |
| 1차 지수 설계(정규화+가중합 또는 이상탐지 방식 결정) | ML | 방법론 선택 및 근거 문서화 |

체크포인트(10/7): 위험지표 정의서와 1차 지수 산출 방법론이 확정되어야 Phase 4(모델링)로 넘어갈 수 있습니다.

## 역할 분담 (4인)

팀장은 PM을 주 포지션으로 맡고, 데이터엔지니어링(DE)·분석/EDA(AN)·모델링(ML)·에이전트설계(AG) 4개 영역에 모두 관여합니다. 팀원 1~3은 포지션이 아직 미정이며, Phase별로 필요한 영역에 유동적으로 배정하는 것을 전제로 합니다.

| 구성원 | 주 포지션 | 관여 영역 | 비고 |
| --- | --- | --- | --- |
| 팀장 | PM(진행관리) | DE·AN·ML·AG 전 영역 | 전 Phase 참여, 최종 의사결정 |
| 팀원 1 | 미정 | 추후 배정 | Phase 1 킥오프에서 강점·관심사 기반 배정 |
| 팀원 2 | 미정 | 추후 배정 | 〃 |
| 팀원 3 | 미정 | 추후 배정 | 〃 |

각 작업 영역(DE/AN/ML/AG)이 실제로 어떤 일을 하는지는 아래와 같습니다. 팀원 1~3이 이 영역들을 나눠 맡으며, 팀장은 PM으로 전 영역에 관여합니다.

| 작업 영역 | 약어 | 핵심 책임 | 주로 활동하는 Phase |
| --- | --- | --- | --- |
| 데이터 엔지니어링 | DE | 데이터 수집·전처리, 격자-행정구역 매핑, 코드 재현성 | Phase 2, 5 |
| 분석/EDA | AN | 탐색적 분석, 코호트 비교, 위험지표 정의 | Phase 3 |
| 모델링 | ML | 예측/분류 모델, 성능평가, 지수 산출 | Phase 3, 4 |
| 에이전트 설계 | AG | 에이전트 로직, 복지자원 매핑, LLM 설계 | Phase 4 |

아래 Phase별 태스크 표의 DE/AN/ML/AG 담당 표시는 특정 인물이 아니라 위 작업 영역을 가리키며, 실제로는 4명이 함께 작업하는 것을 기본으로 합니다. 팀장은 모든 태스크에 PM으로 관여하고, 팀원 1~3의 구체적 영역 배정은 Phase 1 킥오프에서 확정합니다.

## 제출 전 최종 체크리스트

대회 데이터 활용 규칙 기준으로 정리했습니다. 제출 전 팀장(PM)이 최종 확인합니다.

- [ ] 제공 데이터셋(통신 또는 카드) 중 최소 1개를 실제로 사용했는가
- [ ] 외부 공공데이터는 모두 무료·공개 데이터인지 확인했는가(유료 데이터 사용 시 수상 취소)
- [ ] 외부 데이터 출처와 수집 방법을 보고서에 명시했는가
- [ ] 활용한 외부 데이터의 원본 파일을 제출 목록에 포함했는가
- [ ] 가상 데이터(synthetic data)를 생성했다면 생성 방식 설명자료를 첨부했는가
- [ ] LLM/생성형 AI를 활용했다면 구체적 활용 방법과 분석 과정 설명자료를 첨부했는가
- [ ] 분석 결과와 제안 내용을 팀원이 직접 검증·설명할 수 있는 상태인가(질의응답 대비)
- [ ] 재현 가능한 코드(전처리~모델링)를 포함했는가
- [ ] 최소 요구 성과물 4가지(인사이트/데이터근거/모델링/에이전트설계)가 보고서에 모두 포함되는가
- [ ] 보고서 분량·형식이 대회 제출 양식을 따르는가
