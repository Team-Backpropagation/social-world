## 2. 만들기·확인

```bash
python social_world/app/bundle.py                 # → social_world/socialworld-demo.html
python social_world/app/tests/ui_test.py          # 휴대폰·지도·설정·알림
node social_world/app/tests/fishing_test.cjs      # 낚시·인벤토리
node social_world/app/tests/market_test.cjs       # 버스·시장·은행·옷가게
node social_world/app/tests/market_social_test.cjs # 시계·벤치·시장 채팅 UI
node social_world/app/tests/market_chat_window_test.cjs # 창 이동·크기 조절·프로필
python social_world/coco/tests/demo_test.py       # 코코 연결
python social_world/chief/tests/demo_test.py      # 마을이장 연결
```

테스트는 Playwright(크로미움)로 돌고 팀 DB 대신 가짜 supabase를 쓴다. three.js CDN이 막힌 곳이면 `SW_THREE_PATH=경로/three.min.js`.

개발 중에 나눠진 채로 보려면 `social_world` 폴더에서 `python -m http.server 8000` → `http://localhost:8000/app/`.

## 3. 휴대폰 UI가 하는 일 (`ui.js`)

| 기능 | 동작 | DB |
|---|---|---|
| 나의 휴대폰 (오른쪽 아래 버튼) | 홈·동아리·미션·연락처·설정 | — |
| 동아리 | 동아리 목록·멤버 수·가입. "동아리센터로 가기"로 개설 화면 | `clubs`, `club_members` insert |
| 미션 | 미션 목록(환류 추천 미션이 위·추천 표시)·시작·완료, 완료 효과음 | `missions`, `mission_progress` insert/update |
| 주민 연락처 | 루미·정책·취업은 그 NPC 앞으로 이동해 대화, 코코·이장은 바로 대화창 | 앱 대화창이 저장(원문 없음) |
| 전체 지도 (`M`) | 장소를 누르면 입구 앞으로 이동. 내 방에서 누르면 밖으로 나감 | — |
| 설정 | 미니맵 방향(북쪽 고정/회전)·화질·시점 초기화·효과음·키 바꾸기·로그아웃 | 이 브라우저 localStorage(설정 키) |
| 인벤토리 (`I`)·낚시 | 기본 낚싯대 장착·지역별 낚시·개별 크기 유지·분리수거 | 08 SQL 적용 후 Supabase, 적용 전 사용자 ID별 localStorage |
| 코코 알림 | 마을에 들어오고 6.5초 뒤 로그인당 1번, 고정 문구. 누르면 코코 대화창 | — |

- 투어 중이거나 내 방 튜토리얼 중에는 휴대폰·인벤토리 버튼을 숨기고 지도·인벤토리 키도 막는다(튜토리얼 흐름 보호).
- 대화창(NPC·코코·이장)이 떠 있으면 지도 키를 무시하고, 휴대폰·지도·인벤토리가 떠 있으면 캐릭터가 움직이지 않는다. 낚시 중에도 이동은 막지만 상호작용 키는 유지한다.
- 화질·로그아웃 버튼은 HUD에서 빼고 휴대폰 → 설정으로 옮겼다. 시점 초기화(↺) 버튼은 HUD에 그대로 있다.
- **대화 내용·알림 내용은 어디에도 저장하지 않는다.** localStorage `sw_ui_settings_v1`에는 `north·quality·bindings·muted`만. 낚시 아이템·안내 진행은 사용자 ID별 별도 키에 저장한다.
- 코코 알림을 끄려면 `ui.js` 위쪽 `COCO_NOTICE.enabled = false`.

PR #13 시연본과 달라진 점: 예시 데이터(동아리 3개·미션 3개·추천 3개) → 실제 DB, NPC 채팅 화면(입력 막힘) → 앱의 대화창,
"알림 시연" 버튼 → 마을 입장 후 자동 1회, 시연용 미션 자동 완료(공원 도착 등) → 없음.

## 4. 앱과 이어지는 곳

`app.js`가 `WorldUI.init(host)`로 넘기는 것: `sb`, `userId`, `nickname`, `feedback`, `npcs`, `busy`(대화창 열림), `openNpc`, `teleport`, `openMissionRoom`, `openClubRoom`, `logout`, `toast`, `onKeysChanged`.
`app.js`가 부르는 것: `attach(engine)`(3D 시작 때), `sync({inVillage, tour, roomBusy})`(HUD 갱신 때), `isOpen()`(입력 막기), `keyLabel(action)`(HUD 키 표시), `reset()`(로그아웃).

낚시 연결: `tick()`(상태 갱신), `target()`(물가 상호작용 대상), `interactFishing()`(던지기·낚아채기), `isFishing()`(이동 차단), `cancelFishing()`(순간이동·중단). `attach()`는 로그인한 사용자 ID가 바뀌면 기존 낚시 기능을 해제하고 새 인벤토리를 연결한다.

### 5-2. 맵을 넓힐 때 함께 맞출 값

하나라도 빠지면 못 걷거나 지도가 어긋난다.

| 값 | 파일 | 하는 일 |
|---|---|---|
| `VB` | `world-engine.js` | 걸을 수 있는 범위 |
| `buildGrid()`의 `x0, z0, nx, nz` | `world-engine.js` | 자동 길찾기 격자 — `VB`를 덮어야 한다 |
| 땅 크기 `G` | `world-engine.js` | 땅이 덮는 범위 |
| `MAP_B` | `world-engine.js` | 미니맵·전체 지도 그림 범위 |
| `mapPct`(`+58, /116, +34, /92`) | `ui.js` | 전체 지도 위치 계산 — **`MAP_B`와 숫자가 같아야 한다** |
| `RX, RZ` | `world-engine.js` | 내 방 실내 위치 — 넓힌 맵과 겹치지 않게 멀리 |

### 5-3. 주의할 점

- **나무·풀 위치는 난수(`rnd()`) 순서로 정해진다.** `build()` 앞부분에 `rnd()`를 쓰는 코드를 새로 넣으면 뒤쪽 나무·풀 위치가 전부 바뀐다. 새 장식은 따로 난수를 만들어 쓴다(예: 해·구름 블록의 `const rnd = (() => { let q = 7177; … })()`).
- **기존 건물·NPC 좌표는 옮기지 않는 게 좋다.** 튜토리얼 동선, 루미 투어, 코코·이장 위치와 연결돼 있다. 옮겼다면 아래 테스트로 투어·코코·이장이 제자리에 서는지 확인한다.
- `MAP_POINTS`의 x,z는 지도 위 이름표 위치이고, 실제로 서는 자리는 엔진 `places()`(없으면 `EXTRA_SPOTS`)다.

## 7. 버스·별도 시장·은행·옷가게 (2026-10-06)

1차 범위는 버스 왕복 이동, 별도 시장 광장, 두 건물의 3D 실내와 이용 안내 화면이다. 은행 입출금·아이템 창고·옷 구매·가챠·유저 거래·멀티플레이는 추가하지 않았다. 구체적인 업무 규칙을 정한 뒤 확장한다.

### 이용 순서

- 기존 마을 동쪽 남북 도로의 서쪽 승강장 `(47.3, 14.2)`에 노란 버스 표지판이 있다. 전체 지도 `M` → `시장행 버스`로 찾아갈 수도 있다.
- 팻말 근처에서 상호작용 키(기본 `E`) 또는 화면 버튼을 누르면 버스 도착 → 탑승 → 출발 → 검은 화면 → 시장 도착 → 하차 → 버스 출발 순서로 이동한다.
- 이동 중에는 걷기·시점·지도·휴대폰·인벤토리·중복 상호작용을 막는다. `연출 건너뛰기`로 도착 지점까지 바로 이동할 수 있다.
- 시장 광장의 `이음 은행`, `오늘의 옷장` 문 앞에서 상호작용하면 실내로 들어간다. 실내 안내 창구·진열대에서 다시 상호작용해 이용 화면을 연다.
- 실내 출구에서 상호작용하면 시장 광장으로 돌아온다. 시장 지도에는 은행·옷가게·시장 광장·마을행 버스가 표시된다.
- 시장 정류장에서 버스를 불러 기존 마을로 돌아간다. 인벤토리·장착 도구·캐릭터 설정은 유지한다.
- 시장에서 휴대폰으로 미션방·동아리센터 화면을 열었다 닫으면 시장으로 돌아온다.

은행 화면은 보관·저축 창구의 준비 안내이고, 옷가게 화면은 6가지 색상의 진열이다. 잔액·구매·저축 결과를 만들거나 실제 DB에 새 행을 쓰지 않는다.

### 시장 시계·벤치·채팅 UI (2026-10-07)

- 은행 외벽 시계는 입체 케이스·테두리와 3D 시침·분침을 사용한다. 브라우저에서 `new Date()`의 현지 시각을 읽어 1초마다 갱신하므로 사용자의 컴퓨터 시간과 시간대를 따른다. 분침에 초를, 시침에 분·초를 반영한다.
- 시장 광장 일반 벤치는 중앙 등받이와 앞·뒤 좌석을 공유하는 양방향 형태다. 시장 정류장 벤치는 노란 표지판 옆으로 옮겼다. 은행 실내 벤치는 카운터를, 마을 정류장 벤치는 동쪽 도로를 바라본다. 위치·방향에 맞춰 충돌 범위도 함께 바꿨다.
- 시장 광장·은행 실내·옷가게 실내에서 채팅 UI가 보인다. PC에서는 기본으로 펼쳐지고, 모바일에서는 `시장 채팅`을 눌러 펼친다. `Enter`로 입력란에 들어가고 전송하며, `Esc`로 입력을 끝내고 이동한다. 입력 중에는 이동·지도·인벤토리·상호작용 키를 막고 한글 조합을 확정하는 Enter로 미완성 메시지를 보내지 않는다.
- 메시지를 보내면 현재 닉네임으로 채팅창에 표시되고, 캐릭터 머리 위 말풍선이 따라다닌다. 말풍선은 5~9초 뒤 사라지며 시장을 벗어나면 즉시 해제한다. 버스 이동·시장 밖·휴대폰·이용 안내·대화 화면에서는 채팅 UI를 숨긴다.
- 한 메시지는 최대 80자, 최근 기록은 30개다. 현재 페이지의 메모리에서만 유지하며, 로그아웃·새로고침 시 초기화한다. 이번 단계는 자신의 입력을 표시하는 UI 데모이고, 다른 사용자와의 통신은 후속 구현 범위다.
- 새 검증은 `node social_world/app/tests/market_social_test.cjs`. 기존 시장 테스트와 같은 Playwright 및 `SW_THREE_PATH`, `SW_CHROME_PATH`, `SW_PLAYWRIGHT_PATH` 설정을 사용한다. 초기 구현 기록은 `MARKET-SOCIAL.md`, 최신 동작은 이 안내와 소스 코드를 기준으로 한다.


### 시장 채팅창 개선 (2026-10-07)

- 은행·옷가게 내부에서도 메시지를 입력하고 캐릭터 머리 위 말풍선을 볼 수 있다. 같은 시장 안에서는 채팅 기록과 창 위치·크기를 이어서 사용한다.
- 채팅창 상단을 드래그하면 이동하고, 네 변과 네 모서리를 드래그하면 크기가 바뀐다. 화면 밖 이동을 막고 입력란을 사용할 수 있는 최소 크기를 유지한다. 접었다 펼치면 선택한 크기를 복원하며, 화면 크기나 모바일 키보드가 바뀌면 보이는 영역에 맞춘다.
- 메시지의 닉네임 왼쪽에 원형 프로필을 표시한다. 현재 3D 캐릭터의 머리 모델을 96×96 이미지로 렌더링하고 캐릭터 외형이 바뀌면 갱신한다. 원본 캐릭터 머리의 복사본을 사용해 기존 마을의 난수 순서를 바꾸지 않는다.
- 버스 위 이름 말풍선, 옷가게 안 제목 말풍선과 벽에 잘못 걸쳐 있던 거울 판을 제거했다. 실내 출구 안내와 버스 진행 화면은 유지한다.
- 하단 키 안내는 `Enter로 입력 · Esc로 입력 종료 · 최대 80자`로 수정했다. Esc는 채팅 입력을 끝내고 WASD 이동으로 돌아가는 키다.
- 휴대폰에서 사진을 업로드해 프로필을 바꾸는 기능은 협의 전 가안이다. 현재 구현은 캐릭터 얼굴을 기본 프로필로 표시하는 범위다.


## 8. 돈 시스템·온라인 인벤토리 (2026-10-07)

현재 은행 입출금과 옷 구매·착용을 온라인 지갑 및 인벤토리에 연결했다. 실제 팀 DB에는 아직 적용하지 않았으며, 관리자가 `database/08_economy.sql`을 실행하면 활성화된다. 새 온라인 지갑은 시험용 게임 화폐 10,000원을 계정당 한 번 받는다.

- 소지금·예금·물고기별 크기·아이템 소유권·장착 상태를 Supabase에 저장한다.
- DB 적용 전에는 기존 브라우저 낚시·인벤토리를 유지하고, 돈 관련 버튼은 비활성화한다.
- 첫 온라인 연결 때 기존 브라우저 아이템을 계정당 한 번 가져오며 원래 저장값은 보존한다. 이전 아이템은 현재 유저 거래 대상에서 제외한다.
- 요청 ID를 브라우저와 DB에 저장해 통신 실패·재접속 후 중복 차감·지급을 막는다. 온라인 연결 후 통신이 끊기면 로컬에서 새 돈이나 아이템을 확정하지 않는다.
- 거래 제안·수락·취소·거절의 서버 기능 및 클라이언트 함수는 준비되어 있다. 유저 거래 화면은 이번 범위에 포함하지 않았다.
- ‘게스트로 들어가기’로 다른 기기에서 새 계정을 만들면 기존 계정의 데이터와 연결되지 않는다. 기기 간 이용에는 같은 계정으로 로그인하는 흐름이 필요하다.

팀 공유용 변경 내용·전체 DB 구조·적용 절차·검증 결과는 [온라인 경제 변경 정리](../../docs/ONLINE-ECONOMY-CHANGES.md)에 있다. 데모 원본은 이 폴더에서 수정하고 `bundle.py`로 재생성한다.

새 검증: `node database/tests/economy_test.cjs`, `node social_world/app/tests/economy_client_test.cjs`, `node social_world/app/tests/economy_browser_test.cjs`. 테스트 의존성은 위 공유 문서를 참고한다. 테스트는 실제 팀 DB에 접속하지 않는다.


## 9. 탈의실·집 옷장·업적·칭호 (2026-10-08)

- 옷가게 왼쪽 앞 탈의실 안으로 들어가면 별도 3D 착용 화면이 열린다. 근처 E키 또는 옷 구매 화면의 '탈의실에서 입어 보기'도 사용할 수 있다.
- 왼쪽 전신 거울은 현재 캐릭터를 실제로 반사한다. 드래그·방향키로 시점 회전, 휠·두 손가락으로 확대/축소, 시점 초기화와 Esc 닫기를 지원한다.
- 상점에서는 미보유 옷도 무료로 미리 입어 볼 수 있다. 구매와 실제 착용 저장은 각각 명시적으로 선택한다. 닫기는 미리보기만 취소하며 이미 확정한 착용은 유지한다.
- 내 방 앞쪽의 옷장에 E키로 상호작용하면 같은 화면에 보유한 옷과 기본 옷을 표시한다. 옷 6종의 현재 구현은 상의 색상 변경이다.
- 휴대폰 '업적·칭호': 60cm/80cm 직접 낚기, 올바른 분리수거 10/50회. 서버가 달성 여부를 기록하고, 달성한 칭호 중 한 개를 장착하거나 해제한다.
- 시장 광장·은행·옷가게에서는 칭호가 닉네임 위에 표시된다. 말풍선은 그 위에 배치한다. 카메라 행렬 갱신과 위치 추적을 같은 프레임에 맞추고, 크기는 변경 시에만 측정하며 transform으로 이동한다.
- DB는 `08_economy.sql` 다음에 `09_achievements.sql`을 적용한다. 현재 변경은 팀 DB에 자동 적용하지 않는다. 기존 온라인 낚시·분리수거 기록은 반영하며, 브라우저에서 이전한 물고기/분리수거 누계는 업적에 포함하지 않는다. 거래한 큰 물고기의 업적은 원래 잡은 사람이 유지한다.
- 새 파일: `wardrobe.js`, `wardrobe.css`, `wardrobe-reflector.js`(Three.js r149 MIT), `achievements.js`. 기존 게임과 다른 장면의 재질을 공유하지 않으며, 닫을 때 미리보기 자원을 해제한다.
