# 이음 마을 컨셉아트 키트 — 사용법 & AI 요청문

소셜 월드 프로토타입과 **같은 3D 엔진**으로 마을 장면만 떼어 낸 키트예요.
각자 쓰는 AI 도구(ChatGPT, Gemini, Claude, Cursor 등)에 `village-scene.html`과 아래 요청문을 주고 컨셉 후보를 만들어 오면 돼요.
후보들은 모두 같은 틀 안에서만 바뀌기 때문에, 고른 안을 본 프로토타입에 거의 그대로 옮길 수 있어요.

## 0. 빠른 시작 (복사해서 그대로 실행)

Windows는 **Git Bash**에서 실행해요. `minsu`·`겨울마을`만 내 이름·컨셉으로 바꾸면 돼요.

```bash
# ① 처음 한 번만 — 저장소 받기
git clone https://github.com/Team-Backpropagation/social-world.git
cd social-world

# ② 작업 시작 — 최신 main에서 내 브랜치 만들기
git switch main && git pull
git switch -c concept/minsu

# ③ 키트 복사본 만들기 (원본 village-scene.html은 고치지 않아요)
mkdir -p social_world/concept_kit/candidates/minsu
cp social_world/concept_kit/village-scene.html social_world/concept_kit/candidates/minsu/concept_minsu_겨울마을.html

# ④ AI 작업 → 복사본에 반영 (아래 3장 요청문 사용)

# ⑤ 브라우저로 열어 확인·캡처 (파일 탐색기에서 더블클릭해도 돼요)
start social_world/concept_kit/candidates/minsu/concept_minsu_겨울마을.html
#    이름 칸에 "민수_겨울마을" → 화질: 높음 → 9개 장면마다 📸 → 다운로드 폴더에서 옮기기
mv ~/Downloads/민수_겨울마을_*.png social_world/concept_kit/candidates/minsu/

# ⑥ 올리기
git add social_world/concept_kit/candidates/minsu
git commit -m "컨셉 후보: 민수 - 겨울마을"
git push -u origin concept/minsu
#    → GitHub에서 [Compare & pull request] → base: main → 대표 캡처 1~2장 + 한 줄 설명
```

- 후보를 하나 더 만들 땐 같은 폴더에 파일 이름만 바꿔서(`concept_minsu_네온밤.html`) ③~⑥ 반복
- 작업 중 main이 바뀌었으면 내 브랜치에서 `git pull origin main`
- 결과 화면이 하얗다 → AI가 파일 중간을 생략한 것. 3-1 방식으로 돌아가거나 끝부분을 다시 요청

## 2. 진행 순서

1. `village-scene.html`을 열어 원본 모습을 먼저 확인해요. 아래 버튼으로 9개 장면(광장 전경 ~ 내 방)을 볼 수 있고,
   마우스로 끌면 시점을 돌려 볼 수 있어요(휠: 줌). 장면 버튼을 누르면 비교용 기본 각도로 돌아가요.
2. AI에게 **요청문(3장)** + `village-scene.html` + 컨셉 자료를 줘요.
3. 받은 HTML을 `concept_<이름>_<컨셉>.html`로 저장하고 브라우저로 열어요. 예: `concept_minsu_겨울마을.html`
4. 왼쪽 위 입력칸에 후보 이름을 적고, 9개 장면마다 **📸 이 화면 저장**을 눌러요. 파일은 `후보이름_장면.png`로 저장돼요.
5. HTML과 캡처 9장을 `social_world/concept_kit/candidates/<이름>/`에 넣어 PR로 올려요(git이 낯설면 공유 드라이브에 올리고 담당자가 대신 커밋).
6. 팀이 같은 장면끼리 나란히 놓고 비교해 투표해요. 고른 안은 본 프로토타입에 옮겨요(5장).

> 비교할 때는 되도록 **화질: 높음**으로 찍어요. 휴대폰은 기본값이 '가벼움'이라 버튼으로 바꿔 주세요.

## 3. AI에게 붙여 넣을 요청문

### 3-1. 가벼운 버전 — THEME(색·빛·하늘)만 바꾸기 · 모든 도구에서 안정적

```
첨부한 village-scene.html은 three.js(r149)로 만든 3D 마을 장면이야.
이 마을의 분위기를 아래 컨셉에 맞게 바꿔 줘.

[컨셉] (여기에 컨셉 설명, 또는 "첨부 이미지의 색감·분위기")

규칙:
1. 파일 위쪽 <script> 안의 `var THEME = { ... };` 블록만 수정해.
   (하늘 sky, 안개 fog, 빛 light, 땅 ground, 풀잎 grassBlade, 건물 재료색 COL, 식물색 PAL)
2. 키 이름과 구조는 그대로 두고 값만 바꿔. 색은 '#RRGGBB' 형식.
3. 결과는 수정한 THEME 블록 전체를 코드 한 덩어리로 줘. 설명은 짧게 3줄 이내.
```

→ 받은 THEME 블록을 `village-scene.html`의 THEME 블록과 통째로 바꿔 끼우면 끝이에요. 파일이 커서 AI가 전체를 못 돌려주는 경우에도 이 방법은 잘 돼요.

### 3-2. 깊은 버전 — 건물·나무·캐릭터 모양까지 바꾸기 · 긴 코드를 다룰 수 있는 도구에서

```
첨부한 village-scene.html은 three.js(r149)로 만든 3D 마을 장면이야.
아래 컨셉에 맞게 마을의 색과 모양을 바꿔 줘.

[컨셉] (컨셉 설명 / 레퍼런스 이미지)

바꿔도 되는 곳:
- `var THEME = { ... };` 블록의 값
- 코드 안에 "🎨 [꾸미기 구역]" 주석이 달린 부분: 건물·나무·꽃·분수·공원·내 방·캐릭터의 모양, 색, 장식

바꾸면 안 되는 곳:
- 장소 좌표(x, z), 건물 크기와 문 위치
- `colliders.push(...)`, `places.xxx = ...`, `doors.push(...)` 줄 (충돌·길찾기·문 판정에 쓰임)
- NPC id(psych, policy, job, chief)와 api 함수 이름
- 둥근 지평선 셰이더, 틸트시프트 후처리 구조
- three.js 버전(r149 CDN). 다른 외부 라이브러리·이미지 파일 추가 금지(텍스처는 코드로 그리기)

출력 규칙:
- 파일 전체를 처음부터 끝까지 생략 없이 출력해. "…", "(이하 동일)" 같은 생략 금지.
- 전체 출력이 어렵다면 바꾼 함수/블록만 "원래 위치(주석 제목)"와 함께 따로따로 줘.
- 마지막에 무엇을 바꿨는지 5줄 이내로 요약해.
```

### 3-3. 2D·2.5D로 재구성하기 (방향 탐색용)

3D가 아닌 **2D(도트·일러스트 타일맵)** 또는 **2.5D(쿼터뷰·아이소메트릭)** 로 다시 그려 봐도 좋아요.
단, 이 후보는 **"코드 병합용"이 아니라 "방향 결정용"** 이에요. 2D로 결정되면 엔진(화면 그리는 부분)을 새로 만들고,
튜토리얼·투어·NPC 대화 쪽은 그대로 연결해요. 그래서 아래 조건만 지켜 주면 돼요.

**꼭 지킬 것**
1. **장소 구성과 상대 위치는 그대로**: 광장 한가운데 분수, 북쪽 지원센터, 서쪽 미션방, 북서쪽 카페(앞에 루미 자리),
   동북쪽 동아리센터, 동쪽 게임방 천막, 남서쪽 공원 연못, 동남쪽 내 집, 광장 남동쪽 텃밭, 마을 북쪽 강과 다리
2. **같은 9개 장면**으로 캡처: 광장 전경 · 지원센터 · 미션방 · 동아리센터 · 게임방 · 카페·루미 · 공원 · 내 집 · 내 방(실내)
3. **캐릭터가 배경에 묻히지 않게**: 특히 루미(보라 멜빵·꽃 핀·올림머리)와 내 캐릭터. 캐릭터는 2~2.5등신 유지
4. **글자가 읽혀야 함**: 건물 간판(지원센터·미션방 등)과 미션방 벽의 "단계별 퀘스트" 게시판
5. **휴대폰 세로·가로 화면**에서도 한눈에 보일 것

**있으면 좋은 것**
- 걷기(WASD·방향키)와 "땅을 누르면 그곳으로 이동" 흉내 — 느낌만 보여도 충분
- 낮/저녁 두 가지 색감

### 붙여 넣을 요청문

```
첨부한 village-scene.html은 three.js로 만든 3D 마을이야. 이 마을을 [2D 타일맵 / 2.5D 아이소메트릭] 스타일로
다시 만들어 줘. 목적은 아트 방향을 비교하는 거라, 코드 구조는 새로 짜도 돼.

[컨셉] (컨셉 설명 / 레퍼런스 이미지)

지켜야 할 것:
1. 장소와 상대 위치는 원본과 같게: 광장 중앙 분수, 북쪽 지원센터, 서쪽 미션방, 북서쪽 카페(앞에 루미 자리),
   동북쪽 동아리센터, 동쪽 게임방 천막, 남서쪽 공원 연못, 동남쪽 내 집, 광장 남동쪽 텃밭, 북쪽 강과 다리
2. 화면 아래에 장면 버튼 9개(광장 전경, 지원센터, 미션방, 동아리센터, 게임방, 카페·루미, 공원, 내 집, 내 방)를 두고,
   누르면 그 장소가 화면 중앙에 오게 해 줘. 내 방은 실내 장면.
3. 캐릭터는 2~2.5등신. 루미는 보라색 멜빵바지·흰 셔츠·올림머리·꽃 핀. 캐릭터가 배경보다 눈에 띄게.
4. 건물 간판과 미션방 벽의 "단계별 퀘스트" 게시판 글자가 읽히게.
5. HTML 파일 하나로. 외부 이미지 파일 없이 그림은 코드(Canvas/SVG/CSS)로 그리기. 외부 스크립트는 쓰지 않거나 CDN 하나만.
6. 파일 전체를 생략 없이 출력해.
```

> 캡처 도구가 없는 후보는 브라우저 스크린샷(Windows `Win+Shift+S`, Mac `Cmd+Shift+4`)으로 9장면을 찍어 주세요.
> 파일 이름은 `후보이름_장면.png` 규칙을 똑같이 써요.

### 도구별 팁

- **ChatGPT**: 파일을 첨부하고 "Canvas에서 수정해 줘"라고 하면 긴 파일도 비교적 잘 다뤄요. 3-2는 "바꾼 부분만" 방식이 안전해요.
- **Gemini**: 파일 첨부 후 3-1부터 시작하고, 결과가 좋으면 3-2로 넓혀요.
- **Claude / Cursor**: 3-2 그대로 사용해도 돼요.
- 어떤 도구든 결과를 열었을 때 **화면이 하얗거나 비어 있으면** 파일이 중간에 잘린 거예요. "파일 끝부분이 잘렸어, 마지막 300줄을 다시 줘"라고 요청하거나 3-1 방식으로 돌아가요.

## 4. 결과물 확인 체크리스트

- [ ] 9개 장면 버튼이 모두 동작하고, 걸어 다닐 수 있다
- [ ] 건물 문 앞까지 걸어갈 수 있다 (막히면 충돌 줄을 건드린 것)
- [ ] 광장 분수·지원센터·카페·동아리센터·게임방·미션방·공원·내 집이 **원래 위치**에 있다
- [ ] 캐릭터가 건물 뒤에 가려지지 않고 잘 보인다
- [ ] 글자가 잘 읽힌다 (간판, 말풍선)
- [ ] 휴대폰에서도 열린다 (화질: 가벼움)

## 5. 고른 후보를 본 프로토타입에 옮기는 방법

- 3-1(THEME만)로 만든 후보: THEME 값을 엔진의 팔레트 자리에 그대로 옮기면 돼요.
- 3-2로 만든 후보: "🎨 [꾸미기 구역]"만 바뀌었는지 비교(diff)한 뒤, 해당 구역을 엔진(`engine.js`)에 옮겨요.
- 옮기는 작업은 후보 HTML을 Claude(Cowork)에게 주고 "이 후보를 socialworld-demo.html에 적용해 줘"라고 하면 돼요. 옮긴 뒤 튜토리얼·투어 자동 테스트를 다시 돌려 확인해요.

## 6. 평가 기준(투표용 예시)

| 기준 | 질문 |
|---|---|
| 형식 | 3D / 2.5D / 2D — 휴대폰 성능, 제작 기간(2D는 엔진 교체 필요)까지 함께 고려 |
