# 사회적 고립 위험 AI 에이전트 — 데이터 소스 및 지표 설계 노트

> 2026 빅콘테스트 AI데이터활용 분야 「사회적 고립 예방 및 대응을 위한 AI 에이전트 모델 개발」 준비 과정에서 나온 조사·브레인스토밍 내용을 정리한 문서. 대회 제공 데이터(통신·카드, '25.7~12월, 강남구·춘천시)만으로는 고립 위험 판단에 한계가 있다는 문제의식에서 출발해, 보강할 외부 데이터와 지수 설계 방향을 다룬다.

## 0. 실제 테이블 정의서 확인 결과 — 최우선 참고 (2026-09-17, 대회 측 제공 「별첨1/별첨2 테이블 정의서」 기준)

주제설명자료(요약 PDF)만으로 추론했던 내용 중 실제 컬럼 스펙과 다른 부분이 있어 정정함. **이 절이 가장 신뢰도 높은 원천**이며, 이후 절의 내용과 충돌하면 이 절을 따를 것.

### 0-1. 통신(유동인구) 데이터 — 3개 테이블, 서로 축이 분리됨
- `DMP_FLOW_POP_AGE_PCELL_GB` (성연령 유동인구, 10세단위): PK = `STD_YM`(기준년월) + `BLOCK_CD`(소지역코드) + `X_COORD`/`Y_COORD`(UTM-K 격자좌표). 컬럼: 남/여 × 10대~60대이상 유동인구수
- `DMP_FLOW_POP_TIME_PCELL_GB` (시간대 유동): PK 동일 구조. 컬럼: 00~23시 1시간 단위 유동인구수(연령·성별 구분 없음)
- `DMP_FLOW_POP_WKDY_PCELL_GB` (요일별 유동): PK 동일 구조. 컬럼: 월~일 요일별 유동인구수(연령·성별 구분 없음)
- **핵심 제약 1 — 월별 스냅샷이지 일별 시계열이 아님**: 테이블 설명에 모두 "OO **일평균** 유동인구"라고 명시. PK가 `STD_YM`(년월)이므로 이건 "그 달의 하루 평균값"이며, 실제 일별 시계열이 아님. '25.7~12월이면 시점이 **월별 6개**뿐 → 일별 급감·이상탐지 방법론은 통신 데이터만으로는 세밀하게 적용 불가. "이번 달 평균 대비 지난달 평균의 변화" 수준으로만 가능
- **핵심 제약 2 — 세 테이블 간 교차 결합 불가**: 연령성별 테이블엔 시간대 정보가 없고, 시간대 테이블엔 연령성별 정보가 없고, 요일 테이블도 마찬가지. 즉 "20대 여성의 심야 시간대 유동인구"처럼 축을 조합한 지표는 **원천적으로 생성 불가**. 시간대별·요일별 유동인구는 전체 인구 기준으로만 봐야 함
- **핵심 제약 3 — 공간 단위가 시군구명이 아니라 격자좌표**: 시군구명 컬럼이 없고 `BLOCK_CD`(소지역코드) + UTM-K 좌표로만 식별됨. 카드 데이터(시군구명 기반)와 결합하려면 격자→행정구역 매핑(공간조인)이 별도로 필요 — 매핑 테이블 제공 여부 확인 필요(Open Item)

### 0-2. 카드 결제 데이터 — 오프라인 한정 확정 + 트랙(주제)별 스키마 상이
정의서 원문에 명시: **"지역적 범위: 서울시 강남구, 강원도 춘천시 가맹점 카드 결제 건 (오프라인 결제건 한정)"** — 추론이 아니라 원문에 그대로 적힌 확정 사실. 순수 온라인 이커머스·구독료·디지털 상품 결제는 데이터에 없음(2-2절의 추론이 원문으로 확인됨).

정의서 파일 안에 **"주제1_데이터셋2"(기후 취약 상권 트랙용)**와 **"주제2_데이터셋2"(사회적 고립 트랙용)** 두 개의 다른 스키마가 있음 — 우리는 **주제2** 기준으로 봐야 함:

| 항목 | 주제1(기후, 참고용) | 주제2(사회적 고립, **우리 트랙**) |
|---|---|---|
| 집계 단위 | 월별 + 6시간 시간대(00-05/06-11/12-17/18-23시) | **일별**(`TA_YMD`, 20250701~20251231), 시간대 축 없음 |
| 가맹점 위치 | 시군구(`MCT_SGG_CD`) | 시군구(`MCT_SGG_CD`) |
| 고객 거주지 | 없음 | **`CLN_SGG_CD`: 이용고객 거주지(시도 단위, NULL 허용)** — 신규 발견 |
| 성별·연령대 | 있음 | 있음(10세단위) |
| 법인카드 | 언급 없음 | **법인카드 이용 제외** — 개인 소비만 |

- **신규 축 발견**: 고객 거주지(시도 단위)가 있어서 "그 지역 거주자의 소비"와 "외지인(관광객·직장인 등) 소비"를 구분할 수 있음. 단 시도 단위라 정밀도는 낮음(서울/경기/강원 정도)
- **제약**: 우리 트랙 스키마엔 시간대 축이 없음 → "심야시간대 결제 비중" 같은 지표는 카드 데이터만으로는 못 만듦(시간대 축은 기후 트랙 스키마에만 있음). 대신 **일별** 시계열은 있어서(184일치), 일별 이상탐지·변화 탐지는 카드 데이터 쪽이 통신 데이터보다 훨씬 유리함

### 0-3. 종합 판단
- 세밀한 시계열(일별) 분석은 **카드 데이터가 중심**이 되어야 함(통신은 월별 6포인트뿐)
- 시간대(낮/밤) 관점의 분석은 **통신 데이터로만** 가능하나 연령·성별과 조합 불가 → "전체 유동인구의 낮밤 패턴"은 볼 수 있어도 "특정 연령대의 낮밤 패턴"은 안 됨
- 연령대·성별 조합 분석은 **양쪽 다 가능**하지만, 통신은 월별 스냅샷, 카드는 일별 시계열이라 시간 해상도가 다름 → 결합 시 통신 쪽을 월 단위로 맞춰 내려서(down-sampling) 비교해야 함
- 공간 단위(격자 vs 시군구) 및 신규 축(고객 거주지)은 Open Item으로 반영

## 1. 배경: 왜 강남구·춘천시인가

공식 근거는 찾지 못했지만(bigcontest.or.kr에 지역 선정 사유는 공개되어 있지 않음), 조사 과정에서 나온 단서는 다음과 같다.

- **강남구**: SK텔레콤과 강남구청이 2019년부터 운영해온 "독거어르신 ICT돌봄서비스(NUGU)" — AI스피커를 독거노인 가정에 보급해 안부 확인·SOS 알림을 제공하는 사업. 최근 AI 돌봄기기를 1,240대까지 확대 운영 중. SK텔레콤 본사도 강남 소재.
- **춘천시**: 국토교통부 "스마트시티 챌린지 사업"의 예비사업지로 2019년·2021년 두 차례 선정된 이력. 통신사 주도 사업이라기보다 정부 주도 스마트시티 인프라 시범도시에 가까움.
- **데이터 제공사 확인**: bigcontest.or.kr 공식 페이지에서 2026년 AI데이터분석/활용 분야 모두 **"데이터제공: SK텔레콤, 신한카드"**로 명시됨. 2024년(12회) 대회 공지사항에서도 SKT·신한카드가 데이터 제공사로 등장 — 두 회사가 최근 대회에서 반복적으로 데이터를 제공해온 고정 파트너로 추정됨.
- **작년(13회, 2025) 자료와의 비교는 확인 실패**: 2025년 AI데이터활용 분야 주제는 "가맹점별 찰떡 마케팅 전략을 찾아라"(소상공인 마케팅)로 올해와 전혀 다른 주제였음. bigcontest.or.kr의 지난 대회 게시판은 12회(2024)까지만 열람 가능했고, 13회(2025) 아카이브나 지역명 언급 여부는 사이트에서 확인하지 못함. 필요 시 운영사무국(bigcontest@kait.or.kr) 문의 필요.

## 2. 문제의식: 제공 데이터의 한계

- 기간이 '25.7월~12월 6개월로 짧아 계절성·장기추세 파악에 제약
- 통신(유동인구)·카드(결제) 데이터만으로는 "고립"이라는 사회적 상태를 직접 관측하기 어렵고, 행동 변화의 간접 프록시에 그침
- → **인구구조 데이터 + 행정 복지데이터 + 기존 고립탐지 사례의 지표 설계를 결합**해서 보강 필요

## 2-1. 데이터 집계 단위 재확인 — 개인 단위 접근 불가, "지역×인구집단" 코호트가 기본 단위 (2026-09-17 재확인, 0장 실제 스펙으로 상세화됨)

주제설명자료 원문(PDF, 260907) 기준 1차 확인 내용. **세부 컬럼 수준의 정확한 내용은 0장을 우선 참고.**

- **데이터셋1(통신)**: "개인 식별이 불가능하도록 비식별·집계된 형태"로 제공. 공간 단위는 격자(0-1절 참고), 연령대별 유동인구 등 제공
- **데이터셋2(카드)**: "개인 및 개별 가맹점 식별이 불가능하도록 집계·비식별 형태"로 제공. 공간 단위 시·군·구, 가맹점 업종별 집계. 이용고객 연령대·성별 포함
- **주제 설명 원문에도 명시**: "지역 및 **인구집단 단위**의 사회적 고립 위험 신호를 조기에 탐지" / "해당 지역 및 인구집단 단위의 '고립 위험도'를 5단계로 실시간 지수화" — 개인 단위 판단은 대회 취지 자체에 없고, 데이터 구조상으로도 원천 불가능

**결론**: 개인 트래킹은 불가능하며 애초에 요구사항도 아님. 위험도 산출의 기본 단위는 **"지역(시군구/격자) × 인구집단(연령대·성별 등)" 셀 단위 코호트**여야 함. 단, 0-1절에서 확인했듯 통신 데이터는 연령대 축과 시간대 축이 분리되어 있어, 코호트를 "지역×연령대×성별"까지만 잡을 수 있고 시간대까지 넣은 코호트는 통신 쪽에서는 불가능함.

## 2-2. 카드 데이터의 오프라인 한정 — 확정 (0-2절에서 원문으로 재확인됨)

이전엔 "가맹점 위치정보(시군구)" 필드 구성으로 미루어 오프라인 데이터일 것으로 **추정**했었으나, 실제 테이블 정의서 원문에 **"오프라인 결제건 한정"이라고 명시**되어 있어 확정됨(0-2절 참고). 순수 이커머스·구독료·디지털 콘텐츠 결제는 데이터에 없음.

**설계에 미치는 영향**: "대체 사회성"(오프라인 접촉 없이 온라인 소비로 대체) 관련 아이디어는 이 데이터만으로는 직접 구현 불가. "오프라인 카드소비 + 통신 유동인구가 모두 낮은 상태"를 간접 신호로 삼는 쪽으로 스코프 조정 필요. 온라인 대체 사회성을 직접 보려면 외부 공공 통계(초고속인터넷 트래픽, OTT/게임 이용률 등 지역 단위 공개 통계가 있는지 별도 확인 필요) 보강이 필요함.

**주요 발견 — 가설 수정 필요**: 애초 "강남=청년형 고립 / 춘천=고령형 고립"이라는 대비 구도를 가정했으나, 강원일보 보도에 따르면 **춘천시 청년(20~30대) 1인가구 비율이 강원도 내 최고치인 45.4%**로 나타남(강원대·한림대 대학가 영향으로 추정). 즉 춘천도 강남 못지않게 청년 1인가구 비중이 크고, 고령 독거와 청년 자취가 공존하는 이중구조일 가능성이 높음. → KOSIS/행안부 데이터를 실제로 받아 두 지역의 연령대별 1인가구 분포를 직접 비교·검증하는 작업이 다음 단계로 필요.

## 4. 참고할 만한 국내 기존 사례

## 6. 지수 생성 방법론 아이디어

1. **정규화 + 가중합 (전통적 방식)**: 지표별 min-max 또는 z-score 정규화 후 도메인 지식 기반 가중치로 합산. 해석이 쉽고 심사 발표 시 설명하기 용이
2. **지도학습 기반 스코어링**: 고독사 실태조사·위기가구 발굴 실적 등을 타깃 라벨로 삼아 XGBoost 등으로 위험도 예측. "AI 에이전트"라는 대회 취지에 부합하지만, 지역·기간이 안 맞는 라벨 데이터의 희소성이 한계
3. **비지도 이상탐지 (절충안)**: Isolation Forest 등으로 "평소 활동 패턴 대비 이탈도"를 스코어화. 서울시 '안부확인' 서비스의 실제 탐지 로직과 결이 일치. **단, 0-1절 확인 결과 통신 데이터는 월별 6포인트뿐이라 세밀한 이상탐지엔 부적합 — 카드 데이터(일별)를 중심으로 적용하는 게 현실적**
4. 대회 예시(5단계 실시간 지수화)를 따르려면 위 스코어를 분위수(quintile) 기준으로 5단계 구간화하는 방식이 실무적으로 흔히 쓰임
5. **(2-1절 반영)** 위 1~3번 방법론 모두, 분석 단위를 "지역 하나"가 아니라 "지역×연령대×성별 셀" 단위로 잡아야 함. 즉 지수 산출 테이블의 row가 (강남구, 20대, 여성) 같은 코호트여야 대회가 요구하는 "지역 및 인구집단 단위" 지수화에 부합함
6. **(0장 반영) 데이터셋별 시간 해상도 불일치 처리 필요**: 카드(일별) vs 통신(월별)의 시간 해상도가 다르므로, 결합 지수를 만들 때는 통신 데이터를 "월간 배경 지표(baseline)"로, 카드 데이터를 "일별 변화 감지(trigger)"로 역할을 나눠 계층적으로 설계하는 방식을 고려할 만함(예: 통신 데이터로 코호트의 평상시 프로필을 정의하고, 카드 데이터의 일별 이탈로 위험 신호를 트리거)

> **2026-09-23 구현 반영** — 1번(정규화 + 가중합)과 6번(통신=배경 / 카드=트리거)을 조합해 `risk_agent/`에 구현했다. 산출 방식은 통합기획서 12-1.

## 6-1. 은둔·고립 정의 브레인스토밍 — 활동량 감소를 넘어선 재정의 축 (2026-09-17)

"고립 = 활동량 감소"라는 통상적 정의(4-1절 사례 기반)에서 벗어나, 라이프스타일(행동 표면) 축 하나에 갇히지 않도록 여러 축을 병렬로 검토함.

- **자발성 축**: 자발적 은둔(관계를 스스로 회피) vs 비자발적 고립(사별·실직·이혼 등 외부 사건으로 관계 단절). 원인이 다르면 개입 방식도 달라야 함
- **지속기간 축**: 전환기적·일시적 고립(이사·퇴직 직후) vs 만성적 고립. 데이터 패턴상 "급격한 단절"과 "원래부터 낮은 평탄선"으로 구분될 수 있음
- **관계의 질 축**: 관계의 '양'이 아니라 '깊이' 문제 — 약한 유대는 있으나 강한 유대(정서적 지지)가 없는 경우. 데이터로 직접 관측 불가능한 한계를 인정하고 가는 것이 오히려 정직한 접근
- **가시성 축(가면 고립)**: 겉으로는 정상 활동(출근·소비)하지만 관계 깊이가 없는 유형 — 활동량 기반 지표로는 탐지 불가능한 사각지대. 보고서에서 지표의 한계로 명시하면 신뢰도 상승 요인이 될 수 있음
- **대체 사회성 축**: 오프라인 접촉 없이 온라인(게임·커뮤니티·SNS)으로 대체하는 유형. ※ 2-2절/0-2절 재확인 결과, 카드 데이터가 오프라인 한정으로 확정되어 직접 탐지는 불가하고 간접 신호(오프라인+통신 활동 동시 저하)로 스코프 조정 필요
- **발생 계기(트리거) 축**: 취업실패형(청년), 사별형(고령), 은퇴 후 역할상실형(중장년), 질병·거동제약형 — 트리거별 데이터 시그니처가 다를 가능성이 높아 인사이트 서사에 강점
- **능동성 축(은둔 vs 고립 구분)**: 은둔=능동적 회피, 고립=수동적 배제. 이 구분을 명시적으로 정의에 반영하는 것 자체가 차별화 포인트가 될 수 있음

**다음 액션 후보**: 위 축 중 2개를 골라 2x2 매트릭스로 유형화하고, 각 유형이 통신·카드 데이터에서 어떤 시그니처로 나타날지 매핑 → "정의 → 데이터 근거"를 연결하는 구조로 발전. 단, 0장에서 확인된 실제 컬럼 제약(시간대×연령대 조합 불가, 카드 시간대축 부재 등)을 감안해서 "데이터로 실제 구현 가능한 시그니처"인지 먼저 걸러야 함
