## 1. "위험사전"은 두 개다

| | ① 위기 표현 사전 | ② 위험 키워드 사전 |
|---|---|---|
| 잡는 것 | 자살·자해 등 즉각적인 위험 신호(태그 `위기발화`) | 고립 신호 — 태그 9종(무기력·소외감·대화상대없음·장기구직·구직단념·사회적회피·생계부담·고립지속·장기고립) |
| 걸리면 | **LLM을 기다리지 않고** 즉시 109·1577-0199 안내 + `report_crisis()` | 태그·키워드 점수(K) → 심각도 → `npc_sessions` → 위험 탐지 미시 신호 |
| 쓰는 곳 | 자유 입력이 있는 **모든 NPC**(루미, 하루 소통 창구, 이후 RAG 질문) | 루미 |
| 원칙 | 놓치지 않는 게 우선. 오탐은 감수 | 관용어·과장을 보정해 정확하게 |

**출발 상태(10/1)**: 사전 파일 없음. 루미 대본 선택지 11개에 태그·심각도(0.1~1.0)가 직접 들어가 있고, 위기는 선택지 하나로만 잡는다. 근거 매핑표는 10/3에 생겼다(0-1).

### 4-1. 사전 항목 형식 (안)

| 칸 | 뜻 |
|---|---|
| `id` | 항목 고유 id |
| `kind` | `crisis` / `risk` |
| `tag` | 태그 이름(태그 9종 중 하나, 위기는 `위기발화`) |
| `patterns` | 표현 패턴 — 띄어쓰기·어미 변화·반복 글자·줄임말을 정규화한 뒤 매칭 |
| `grade` | 위기 사전만 — `strong`(즉시 위기) / `ambiguous`(LLM 맥락 판정) / `idiom`(관용 예외, 위기 아님). 6-1 ① |
| `dimension` | 위험 키워드만 — 정서·사회·행동·경제·지속(다른 차원 가산용, 매핑표 3절) |
| `exclude` | 걸리면 안 되는 표현(관용어 등) |
| `base_severity` | 기본 심각도 0~1 |
| `examples` | 대표 예문(가상 문장) |
| `source` | 근거 자료(문항 번호·문서명) |
| `status` | `draft`(출처 확인 전) / `confirmed` |

### 4-2. 매처가 돌려주는 것

`{ crisis: "strong"|"ambiguous"|null, tags: [...], K: 0~1, mitigated: bool }` — **원문은 돌려주지도 저장하지도 않는다.**
판정은 Python 판단 서버에서만 한다(10/7 결정 — 브라우저 매처 없음). `ambiguous`는 즉시 위기로 처리하지 않고 LLM에 "확인 필요"로 넘긴다.

### 4-3. 심각도 연결 (설계 문서 8-3절)

`severity = min(1, 0.5·K + 0.5·T + 지속성)` — K는 이 사전, T(톤)는 루미 LLM 단계에서 들어간다. 지속성은 그 세션에서 위험 태그가 붙은 발화 수로 센다(3~4번째 +0.1, 5번째부터 +0.2). 위기면 1.0.
구간: < 0.45 일반 대화 / 0.45~0.8 연결 제안(세션당 1번) / ≥ 0.8 강한 연결 제안. **109 안내는 위기 판정일 때만**(6-1 ④). 규칙 전체는 `위험사전_근거_매핑표.md` 3절.
기존 코드 `social_world/common/npc/severity.js`·`severity_config.json`은 10/7 이전 규칙이다 — Python으로 옮기면서 개정 규칙으로 고친다.

## 6. 킥오프 결정 (2026-10-07~08)

### 6-1. 확정

| # | 항목 | 결정 |
|---|---|---|
| ① | 관용어("죽겠다"류) | 위기 사전 항목을 **3등급**으로 나눈다. `strong`("죽고 싶다", 자해 표현 등) = 즉시 위기 대응 / `ambiguous`(맨 "죽겠다", "사라지고 싶다" 등) = 즉시 대응하지 않고 LLM이 앞뒤 맥락으로 판정("우울해 죽겠다" → 위기, "배고파 죽겠다" → 아님), **LLM 실패·시간 초과면 위기로 처리** / `idiom`("배고파·웃겨·더워 죽겠다" 등 확실한 관용 조합) = 위기 아님. 관용어 음성 예문의 오탐률은 숫자로 기록한다 |
| ② | 위기 판정 뒤 대화 | **안내 후 계속.** 위기 안내 배너는 대화창 위에 고정, 루미는 짧은 공감 + 상담 창구 연결을 다시 권함. 다시 감지되면 안내 반복, `report_crisis()`는 세션당 1번 기록 |
| ③ | 저장소 공개 범위 | **비공개.** 위기 예문 파일은 비공개로 두고, 설명이 필요하면 샘플 몇 줄만 올린다 |
| ④ | 높은 심각도 구간의 대응 | 109(자살예방) 안내는 **위기 판정(사전 `strong`, `ambiguous`+LLM 확인, LLM `crisis_suspect`)일 때만**. 위기 표현 없이 심각도 ≥ 0.8이면 "강한 연결 제안"(1577-0199 정신건강 위기상담, 하루) |
| ⑤ | 연결 제안 기준 | 0.5 → **0.45**. 연결 제안은 **세션당 1번**(거절하면 그 세션에서 다시 안 함). 위기 대응은 횟수 제한 없음 |
| ⑥ | 기간 표현 | 한 표로 통일(매핑표 3-2). "몇 주"는 기간 태그 없음, "몇 달째·반년·계속·맨날" → 고립지속("계속·맨날"은 다른 위험 태그가 있을 때만, 10/8), "1년 넘게·몇 년째" → 장기고립. **기간 태그는 하나만**(긴 쪽). 루미 대본도 이 표를 따른다 |
| ⑦ | 여러 태그 가산 | **다른 차원**(정서·사회·행동·경제·지속)이 하나 더 있을 때마다 +0.1, 최대 +0.2. 같은 차원끼리는 가산 없음 |
| ⑧ | 지속성 가산 | 같은 태그가 아니라 **위험 태그가 붙은 발화 수**로 센다. 3~4번째 +0.1, 5번째부터 +0.2(최대) |
| ⑨ | 판단 코드 언어 | **Python 하나**(사용자 10/7). 매처·심각도·LLM 호출을 Python 판단 서버에서 한다. 테스트 서버는 Colab, 시연·배포 서버는 미정. JS 매처는 만들지 않는다 |
