## 1. 용어 규칙

| 용어 | 누구의 것 | 누가 보나 | 표기 |
|---|---|---|---|
| **위험도** | 코호트(지역×연령대×성별) | 관리자만 | `Lv.1 안심` ~ `Lv.5 위험` |

 🎮 게임방 ── 🏘 광장 ── ☕ 카페
  게임모임       │      대화 / NPC
                 ├── 📋 미션방

            🎸 동아리센터

                 │
            🏛 지원센터

| 미션방 | 퀘스트 1~4단계 진행·확인, 이장 이벤트 참여 기록 | — | 미션방(유지) |

## 3. NPC 4종

| 캐릭터 | 역할 | 기존 NPC | 핵심 기술 | 위험 탐지 에이전트로 보내는 것 |
|---|---|---|---|---|
| **마을이장** | 월드 내 유저 활동량·관심사를 보고 활동·이벤트를 제안 + 결과를 위험 탐지 에이전트에 전달 | (신규) — ⑩ 환류의 월드 창구 | 규칙 기반 이벤트 결정 + LLM 대사 생성 | 코호트별 활동량, 퀘스트 단계 분포, 이벤트 참여율, 스티커 수 |
| **루미** (친구) | 일상 대화, 심리 상담 보조, 위험 키워드 탐지 + 결과 전달 | 심리상담 NPC | 대본 + LLM 하이브리드, 위험 키워드 사전 | 키워드 태그, 심각도, 위기 발생(user_id 없음) |
| **하루** (복지) | 정책·취업지원·민원 안내 및 추천 | 정책추천 + 취업상담 + 민원챗봇 | RAG, 추천시스템 (+ 공통 위기 검사) | 조회 카테고리, 추천→신청 전환, 자격 미달 수요 **[확정]** — 위험 신호가 아니라 **수요 신호** |
| **코코** (활동) | 관심사 기반 동아리·모임·챌린지·지역 행사 추천 | (신규) — 동아리·미션 안내 | RAG, 추천시스템 | 추천 카테고리, 추천→참여 전환 **[확정]** |

### 3-1. 코코와 마을이장의 경계

둘 다 "활동 제안"이라 겹치기 쉽다. 경계는 **대상과 생성 여부**다.

| | 코코 | 마을이장 |
|---|---|---|
| 대상 | 사용자 한 명 | 월드 전체 또는 특정 코호트 |
| 하는 일 | **이미 있는** 동아리·모임·행사 중에서 골라 추천 | **새 이벤트를 만들어** 모두에게 연다 |
| 예시 | "러닝 좋아하면 목요일 러닝크루 어때?" | "토요일 공원에서 같이 걷기 이벤트를 열었어요" |

### 3-2. 마을이장의 입력 — 양방향 **[확정 9/29]**

마을이장이 월드 안 데이터만 보면 "통신·카드 분석 결과가 월드 운영에 반영된다"는 차별점이 빠진다. 입력을 둘로 둔다.

- 월드 내부: 활동량, 관심사 분포, 퀘스트 진행, 이벤트 참여
- 위험 탐지 에이전트 환류: `cohort_feedback`(코호트별 추천 NPC·미션). **위험 등급·점수 자체는 받지 않는다**

→ 이장은 월드 ↔ 위험 탐지 에이전트를 **양방향으로 잇는 창구**가 된다.

**받는 창구는 이장 하나로 [확정 9/29]** — 신호는 네 NPC 모두 위로 올리지만(루미: 키워드·심각도, 하루: 복지 수요, 코코: 활동 수요, 이장: 월드 활동), 환류를 **받는** 것은 이장뿐이다. 이장이 환류를 해석해 "이번 주는 하루를 먼저 보여줘" 같은 강조를 다른 NPC에 나눠 준다. 하루·코코·루미는 위험 등급을 직접 보지 않는다.

- 발표에서 "이장 = 월드를 운영하는 에이전트"로 한 줄 설명이 된다
- 환류 경로가 하나라서 등급 노출 위험이 줄고 테스트가 쉽다
- 기획서 6-2 ⑤(하루 랭킹에 위험도 등급 사용)는 "이장이 준 강조 가중치"로 대체한다

### 3-3. 마을이장 월드 리포트 **[확정 9/29]**

이장이 **이미 집계된 숫자만** 읽고, "이번 주 월드에서 무슨 일이 있었나"를 문장으로 써서 관리자 대시보드에 **해설로** 붙인다. 숫자 자체는 지금처럼 DB 집계 함수가 위험 탐지 에이전트로 바로 올린다(이장을 거치지 않는다).

| 항목 | 내용 |
|---|---|
| 입력 | 코호트×주 집계만 — 루미 키워드·심각도(`npc_chat_metrics`), 하루·코코 수요, 월드 활동(퀘스트 단계, 이벤트 참여율, 응원 스티커). k=5 미달 코호트는 제외. 개인 행·대화 원문은 읽지 않는다 |
| 출력 | 코호트별 3~5문장 해설 + 월드 전체 요약 1단락 |
| 생성 | 숫자는 템플릿이 넣고, LLM은 문장만 쓴다(LLM이 숫자를 바꾸지 못하게). "AI가 작성한 해설" 라벨 표시 |
| 역할 한계 | 위험 점수·등급 계산에 들어가지 않는다. 담당자가 읽는 참고 설명일 뿐 |
| 주기 | 위험 탐지 산출 주기와 같게(주 1회) |
| 저장 | `world_reports` (`database/03_world_update.sql`) — 문장 + 숫자 원본(`stats`) |
| 대시보드 위치 | 코호트 상세에 "소셜 월드에서 보인 모습" 섹션 추가, 요약 영역에 월드 전체 요약 |

**발표 표현**: DB 집계 함수를 "이장의 장부"로 부른다 — "마을이장이 월드를 취합해 보고한다"는 그림은 살리고, 개인 데이터는 이장에게 모이지 않는다.

### 3-4. 하루·코코의 추천 방식

시연 규모에선 사용 이력이 거의 없어 협업 필터링은 쓸 수 없다(콜드 스타트). **콘텐츠 기반 + 규칙 점수**로 간다.

| | 하루 | 코코 |
|---|---|---|
| RAG 지식베이스 | 복지로·온통청년·강남구/춘천시 지원사업, 취업지원 프로그램 | 월드 내 동아리 소개, 지역 문화행사·러닝크루 등 모임 정보 |
| 추천 입력 | 프로필(지역·연령대) + 대화에서 뽑은 니즈 + 코호트 환류 | 프로필 + 관심사(온보딩·루미 대화) + 활동 이력 |
| 1차 필터 | 자격요건(연령·거주지 등) — 자격 미달 추천은 신뢰 훼손 | 거리·시간대·인원 |
| 점수 | 상황 적합도 + 신청 난이도 + 환류 가중 | 관심사 일치 + 참여 난이도(퀘스트 단계에 맞춤) |

## 4. 퀘스트 1~4단계

온라인 행동 → 가벼운 상호작용 → 커뮤니티 → 오프라인 연결로 점진적으로 넘어간다. 미션방에서 진행·확인한다.

| 단계 | 이름 | 퀘스트 예시 | 비고 |
|---|---|---|---|
| 1단계 | 첫걸음 | NPC에게 말 걸기 · 광장 방문 · 관심 동아리 둘러보기 | |
| 2단계 | 인사 | 다른 유저에게 이모지 보내기 · **동아리에 응원 스티커 남기기** · 루미와 오늘 있었던 일 이야기하기 | 게시판 글쓰기 → 응원 스티커로 교체 |
| 3단계 | 모임 | 온라인 소모임 참여 · 러닝 챌린지 참여 · 취미 동아리 가입 | |
| 4단계 | 동네로 | 실제 지역 프로그램 참여 · 청년센터 프로그램 신청 · 상담·복지서비스 알아보기 | 6절 방식으로만 |

퀘스트 진행 기록은 코호트 단위로 집계해 "게임 활동 = 고립도의 행동 신호"(통합기획서 6-7)로 위험 탐지 에이전트에 들어간다.

## 5. 동아리 응원 스티커 (게시판 대체)

- 동아리센터의 각 동아리 카드에 **정해진 스티커만** 남긴다: 👏 멋져요 · 🙌 나도 해보고 싶어 · 💪 응원해 · 🌱 천천히 해도 돼
- 자유 텍스트 없음 → 악플·위기 글 관리 부담이 없다
- 같은 동아리에 하루 1회. 동아리 운영자는 받은 스티커 수를 본다
- 로그: 스티커 수를 코호트×주 단위로 집계해 이장 입력·위험 탐지 신호로 사용(k=5)
- DB: `club_cheers` + 개수 뷰 `club_cheer_counts` (`database/03_world_update.sql`) — 본인 행만 읽기·쓰기, 개수만 공개

## 6. 오프라인 연결 (4단계)

우리 원칙은 "개인 식별정보 미보관 · AI가 개인에게 직접 개입하지 않음"이다. 그래서 **게임이 대신 신청하지 않는다.**

1. 하루(또는 코코)가 프로그램을 안내한다 — 내용·자격·일정·신청처
2. **실제 신청 페이지 링크**를 새 탭으로 연다
3. 사용자가 직접 신청한다. 시스템은 신청 정보를 받지 않는다
4. 돌아와서 **"신청했어요"** 버튼 → 퀘스트 완료(자기보고)

발표 표현은 "자동 연계"가 아니라 **"연결 안내"**.

## 7. 월드 이벤트 문구 원칙

| 시민 화면 (광장 공지·이장 대사) | 관리자 대시보드 |
|---|---|
| 🌙「금요일 밤 산책 챌린지」 금요일 저녁, 공원에서 같이 걸어요. 말 안 해도 괜찮아요. | 생성 근거: 강남구 20대 남성 Lv.5 · 주요 요인 명절 이벤트 무반응(H-A) · 이벤트 목적: 저부담 오프라인 접촉 |

**쓰지 않는 표현**: "혼자 지내는 주민이 늘었어요", "외로운 분들을 위해", "위험", "고립", "20대 남성 대상" 등 — 특정 집단의 상태를 드러내거나 낙인이 될 수 있는 말. 대상 코호트를 노출하지 않고, 이벤트는 누구나 참여할 수 있게 연다(노출 우선순위만 조정).

## 8. 하이브리드 NPC 설계

### 8-1. 적용 범위

네 NPC 모두 "선택지 뼈대 + LLM" 구조이고, **LLM이 맡는 범위**만 다르다. 하루·코코는 RAG를 쓰는 순간 LLM이 응답을 만든다.

| NPC | 뼈대 | LLM이 하는 일 | 이유 |
|---|---|---|---|
| 루미 | 대본 선택지 | **자유 입력 대화** + 키워드·톤 판정 | 위험 발화는 선택지로 다 못 잡는다 |
| 마을이장 | 규칙이 이벤트를 **결정** | 이벤트 안내·잡담 **대사 생성**(짧게) | 월드를 생생하게. 결정은 규칙에 두어 설명 가능성 유지 |
| 하루·코코 | 카테고리 선택지 | RAG 검색 결과로 근거 기반 응답 | 사실관계는 반드시 검색 문서 근거 + 출처 |

이장까지 하이브리드로 두는 것에 찬성한다. 단 이장은 **자유 대화창 없이** 대사만 생성해도 생생함은 충분하고, 위기 발화가 이장에게 들어올 경로가 줄어 안전하다.

**하루·코코의 위험 탐지 범위** — 루미처럼 심각도 점수를 매기지 않는다. 자유 입력에는 **공통 위기 검사(8-2 ②)만** 걸고, 위기면 즉시 위기 대응, 힘든 기색이 있으면 루미를 권한다. 이들이 올리는 로그는 위험 신호가 아니라 수요 신호다.

### 8-2. 구조

```
[브라우저] 선택지 클릭 ─────────────────────────► 대본 응답 (지금과 동일)
          자유 입력 ─► Supabase Edge Function `npc-chat` (API 키는 여기에만)
                         ① 개인정보 마스킹 (전화번호·이메일·실명 패턴)
                         ② 위기 표현 사전 선검사 ─ hit ─► 즉시 위기 대응 (report_crisis, 109 안내)
                         ③ OpenAI 호출 (구조화 출력 JSON)
                              { reply, tags[], keyword_score, tone_score, idiom_flag }
                         ④ 심각도 계산 (8-3) ─ 임계 초과 ─► 위기 대응
                         ⑤ npc_sessions에 태그·심각도만 저장 (원문 저장 안 함)
                         ⑥ 실패/타임아웃 ─► "조금 더 얘기해 줄래?" + 대본 선택지로 복귀
```

- "NPC 대화는 반드시 백엔드를 거친다" 원칙 유지. 브라우저에 API 키 없음
- 저장 칼럼은 기존 `npc_sessions`(`risk_keyword_count`, `severity_score`, `keyword_tags`) 그대로 → 위험 탐지 에이전트 수정 불필요
- 위기 판정은 **규칙 사전이 먼저**. LLM 응답을 기다리지 않는다. OpenAI moderation의 self-harm 카테고리를 2차 검사로 쓰는 것도 후보(한국어 성능 확인 필요)
- 원문은 답변 생성을 위해 OpenAI API로 전송된다 → 9절 상세 고지에 반드시 포함. API 데이터 보관·학습 정책은 도입 시점에 확인해 문구에 반영

### 8-3. 심각도 = 위험 키워드 + 발화 톤 **[잠정값]**

| 요소 | 산출 | 설명 |
|---|---|---|
| K 키워드 점수 | 사전 매칭(태그별 기본 심각도, 0~1) | 기존 10종 태그: 무기력·소외감·대화상대없음·장기구직·구직단념·사회적회피·생계부담·고립지속·장기고립·위기발화 |
| T 톤 점수 | LLM 판정(0~1) | 절망감·무기력·자기비하·미래 부정·단절 표현의 강도 |
| 관용어 보정 | LLM `idiom_flag` | "배고파 죽겠다" 같은 관용 표현이면 K를 절반으로 |
| 지속성 | 같은 세션 내 반복 | 같은 태그가 3회 이상이면 +0.1 |

```
severity = min(1, 0.5·K + 0.5·T + 지속성 가산)
위기 사전 hit → severity = 1.0 (계산 생략)
```

| 구간 | 루미의 대응 |
|---|---|
| < 0.5 | 일반 대화 |
| 0.5 ~ 0.8 | 공감 + 하루(상담·복지 안내) 또는 전문 상담 창구를 부드럽게 제안 |
| ≥ 0.8 | 위기 대응: 109·1577-0199 안내 + `report_crisis()`(지역·시각·NPC만) |

가중치·임계값은 `config`에 두고 검증셋으로 조정한다. "학습"이라는 표현은 쓰지 않는다(통합기획서 5-1).

## 9. 안내 문구 (반감 없는 버전)

원칙: **감시·분석·위험** 같은 단어를 쓰지 않는다. 짧게, 친구 말투로. 숨기지는 않는다(상세 안내에 다 적는다).

**루미 첫 대화 (최초 1회, 닫기 가능)**
> 안녕, 나는 루미야. AI 친구라서 사람 상담사는 아니야.
> 우리가 나눈 말은 저장하지 않아. 대화 분위기만 이름 없이 모아서, 우리 동네에 어떤 모임이나 지원이 있으면 좋을지 찾는 데 써.
> 혹시 더 큰 도움이 필요해 보이면, 믿을 만한 곳을 같이 찾아볼게.

**입력창 안내 문구**
> 편하게 적어 줘. 말하기 싫은 건 안 써도 괜찮아.

**ⓘ 자세히 보기 (펼침)**
> - 루미의 답은 AI(OpenAI)가 만들어요. 답을 만들기 위해 입력한 글이 AI 서비스로 전달돼요.
> - 전화번호·이메일 같은 개인정보는 보내기 전에 가려요.
> - 대화 원문은 저장하지 않아요. "요즘 기운이 없음" 같은 분위기 표시만 이름 없이 남고, 같은 동네·또래가 충분히 모였을 때만 통계로 쓰여요.
> - 이 통계는 지자체가 청년 모임·지원 프로그램을 준비하는 데 쓰여요.

**부드러운 연결 제안 (심각도 0.5~0.8)**
> 요즘 많이 지쳤구나. 이런 얘기를 더 잘 들어줄 수 있는 곳이 있는데, 궁금하면 알려줄까?

**위기 대응 (≥ 0.8)**
> 지금 많이 힘든 것 같아. 혼자 견디지 않아도 돼.
> 지금 바로 이야기할 수 있는 곳이 있어: 📞 109 (자살예방상담, 24시간) · 📞 1577-0199 (정신건강 위기상담)
> 루미도 여기 있을게.

## 10. 발표용 데이터 예시 — 강남구 20대 남성

실제 청년 8개 코호트 결과(`risk_agent/outputs_youth/risk_scores.csv`)에서 강남 20대 남성은 **Lv.5 위험**으로 나온다. 다만 그대로 "고립 발견"으로 말하면 안 된다.

| 항목 | 값 | 의미 |
|---|---|---|
| 등급 | Lv.5 (8개 중 상위) | 등급이 **분위수(상대 순위)**라서 8개 중 누군가는 반드시 Lv.5가 된다 |
| 점수 | 54.7 (8개 범위 42~55) | 집단 간 차이가 작다 |
| 입력 z | 통신 0.61 · 카드 −0.65 · 명절 반응 1.00 | 모두 ±1.5 안 → 평소 대비 뚜렷한 이탈은 아님 |
| 주요 요인 | 명절 이벤트 무반응(H-A 의심) | 추석 등 이벤트 때 소비 변화가 또래보다 작음 |

노션 예시의 "야간 이동량 감소 · 주말 외출 감소 · 외식/문화 소비 감소"는 이 결과와 다르다. 통신 데이터는 연령·성별과 시간대를 조합할 수 없어 "20대 남성의 야간 이동"은 원천적으로 계산이 안 되고, 카드 활동(z −0.65)은 오히려 줄지 않았다.

**권장 발표 문장**
> 실제 데이터에서 강남구 20대 남성이 청년 8개 집단 중 가장 높은 Lv.5로 분류되었습니다. 주요 요인은 명절 등 이벤트 시기에 소비 변화가 또래보다 작은 '이벤트 무반응' 패턴입니다. 절대적 이탈 폭은 크지 않아, 에이전트는 즉시 개입보다 '추가 확인'과 저부담 월드 이벤트를 먼저 제안합니다.

이 흐름이 월드로 이어지면: 이장이 부담 없는 공원 산책 이벤트를 열고(시민에겐 중립 문구), 대시보드에는 근거가 표시된다.

### 13-1. 사전 설문 **[확정 9/29]**

평범한 설문 형태(한 화면에 한 문항, 진행 막대)로 간다. "입주 신청서" 같은 게임 포장은 게임 컨셉이 정해지면 다시 본다.

| # | 질문 | 선택지 | 필수 | 쓰임 |
|---|---|---|---|---|
| 1 | 소셜 월드에서 쓸 이름 | 직접 입력 | ✅ | 닉네임 |
| 2 | 어느 지역에 살고 있나요? | 서울시 강남구 / 강원도 춘천시 / 다른 지역 | ✅ | 코호트 |
| 3 | 나이대 | 20대 / 30대 / 그 외 | ✅ | 코호트 |
| 4 | 성별 | 여성 / 남성 | ✅ | 코호트 — "응답 안 함"이 쌓이면 통신·카드 데이터와 연결되지 않아 **필수** |
| 5 | 어떤 분위기가 좋아요? + 좋아하는 색 | 아늑한·활발한·차분한·엉뚱한 + 6색 | ✅ | 캐릭터 1차 생성 |
| 6 | 요즘 관심 있는 것 (최대 3개) | 운동·게임·음악·독서·요리·취업·공부·휴식 | 건너뛰기 가능 | 코코 추천, 이장 이벤트 주제 |
| 7 | 소셜 월드에서 뭘 해보고 싶어요? | 쉬고 싶어요 / 이야기 나누고 싶어요 / 새로운 사람 / 필요한 정보 | 건너뛰기 가능 | 루미가 먼저 소개할 곳 |
| 8 | 요즘 하루는 어때요? | 여유로워요 / 바빠요 / 좀 지쳤어요 / 잘 모르겠어요 | 건너뛰기 가능 | 루미 첫 인사 말투만. **저장하지 않음** |

- "다른 지역"(`sgg_code='OTHER'`)·"그 외"(`age_group='기타'`)는 이용은 되고, 위험 탐지 집계에서만 빠진다
- 1인 가구·취업 상태·소득은 묻지 않는다 — 하루가 대화 중 필요할 때 묻는다
- 외로움·우울 척도 문항은 묻지 않는다 — 신호는 루미 대화에서 모은다
- 저장: `profiles.avatar`·`interests`·`join_goal` (`database/03_world_update.sql` A-4)

### 13-2. 캐릭터 생성 **[확정 9/29]**

- **캐릭터 분위기는 취향 답으로만 정한다.** "좀 지쳤어"라고 답했다고 어두운 캐릭터를 만들지 않는다(상태를 외모로 드러내지 않기)
- 1차 생성은 **규칙 매핑**: 취향 답 → 미리 만든 부위 조합(헤어·얼굴·옷·색). 이미지 생성 AI는 쓰지 않는다(일정·저작권·품질 편차)
- 꾸미기 에셋은 무료 CC0 에셋팩(통합기획서 9장의 Kenney 등)에서 부위별로 준비. 프로토타입은 SVG 도형 조합(머리 모양 5·머리색 6·피부색 4·옷 색 6·소품 6·표정 4)
- 분위기 → 1차 조합: 아늑한=긴 머리·비니·미소 / 활발한=삐죽 머리·모자·활짝 / 차분한=짧은 머리·안경·차분 / 엉뚱한=곱슬·헤드폰·윙크. 옷 색은 고른 색, 피부색은 이름으로 정한 기본값
- 저장: `profiles.avatar jsonb`

### 13-3. 루미의 월드 소개 **[확정 9/29]**

### 13-5. 3D 마을 적용 (2026-09-29)

"이음 마을" 3D 컨셉(아티팩트)의 장면을 데모에 옮겼다. 둥근 지평선·바람에 흔들리는 풀·틸트시프트 후처리·큰 머리 2등신 캐릭터는 원본 그대로이고, 새 맵과 튜토리얼을 얹었다.

| 공간 | 3D에서 | 비고 |
|---|---|---|
| 광장 | 가운데 분수 광장 | 마을이장·정책추천·취업상담 창구 |
| 지원센터 | 원본 주민센터 건물(북쪽) | 안은 준비 중 |
| 미션방 | 원본 미션방(서쪽) | 들어가면 미션 화면. 게시판에 "단계별 퀘스트" |
| 동아리센터 | 원본 동아리방(북동쪽) | 들어가면 동아리 화면 |
| 게임방 | 원본 미니게임 천막(동쪽) | 준비 중 |
| 카페 | 새로 지음(북서쪽) | 루미가 앞에 서 있다. 카메라 쪽(남쪽)에 두면 지붕이 캐릭터를 가려서 북쪽에 둠 |
| 공원 | 연못·벤치(남서쪽) | 준비 중 |
| 내 집 → 내 방 | 새로 지음(동쪽) → 3D 실내(침대·책상·책장·창문) | 원본 게시판은 폐지 결정에 따라 뺐다 |

- 튜토리얼: 설문 → 캐릭터(3D 미리보기로 꾸미기) → 내 방 침대에서 깨어남(Z z z) → 루미가 "똑똑!" 하고 문으로 걸어 들어와 인사 → "같이 걸어보자" → 집 앞으로 나가 루미가 앞장서고 유저가 따라 걷는 8곳 투어(금색 표시) → 마지막에 마을이장께 인사 = 첫 퀘스트
- 이동: WASD·방향키, 땅을 누르면 그곳으로, "루미 따라가기"는 자동으로 걸어감. 길찾기는 0.5칸 격자 A*라 건물·울타리·벤치를 돌아간다
- 가까이 가면 "대화하기 (E)"/"들어가기 (E)" 버튼. 미션방·동아리센터는 기존 화면으로 들어가고 나오면 그 문 앞에서 다시 시작
- 화질 버튼(높음/가벼움). 휴대폰은 기본 가벼움. WebGL이 없는 기기는 안내 화면 + 미션방·동아리센터만 제공
- 검증: Supabase 목업 + 소프트웨어 WebGL로 Playwright 14항목(튜토리얼 전체·8곳 도보 투어·첫 퀘스트 기록·"요즘" 미저장·WebGL 없음·모바일) + 문 출입 동선 확인
- 한계: 공원·게임방·카페·지원센터 안은 아직 없음, 하루·코코 캐릭터 없음(정책추천·취업상담 창구가 임시), 저사양 기기 성능 미측정
