## 3. 확정된 핵심 설계 (왜 이렇게 했나)

### 3-1. 데이터 제약과 활용 전략
- **통신 = 배경지표(baseline)**, **카드 = 트리거(trigger)**. 통신은 월 6점뿐이라 일별 이상탐지 불가, 카드는 184일 일별. 변동성 2.3배 차이.
- 통신의 연령성별·시간대·요일 테이블은 서로 조합 불가 → "20대 여성의 심야 유동" 같은 지표는 원천 불가.
- **거시·미시 2층**: 거시(대회 데이터, 비식별 집계)는 "어디·누가 위험한가", 미시(소셜 월드 대화, 익명 집계)는 "왜·무엇이 필요한가". 대회 데이터엔 텍스트도 개인도 없으므로 미시는 독립 신호원.
- 가상데이터(synthetic)는 대회 규칙상 허용, 단 **생성 방식 설명자료 제출 필수** → 작성 완료.

### 3-2. EDA 결론 → 지표 설계 원칙 (`데이터_분석근거_정리.md` 9장)
1. 정규화 필수(코호트 규모 격차 최대 1,400배) 2. 요일 보정 필수(~24%p) 3. 공통 성분 제거(원거리 코호트 리듬 상관 0.847)
4. 명절은 총량보다 **구성**을 바꾼다(춘천 추석 총량 +2.4%인데 업종 구성 대격변) 5. 업종 지표는 추세가 아니라 **이벤트 반응도**로
6. 통신=배경, 카드=신호 7. baseline에서 연휴 제외 8. 거주여부는 금액·건수 기준으로만
9. **건수 기반 + 고정지출(세금·보험·통신요금·등록금 등) 제외** — 금액은 세금공과금(금액 28%)에 지배됨
10. **코호트 간 비교보다 코호트 내 시간 변화** — 연령 교란 잔존

가설: **H-A** 이벤트 무반응형 / **H-B** 필수소비 편중(선택소비 위축)형 / **H-C** 구조적 저활동형.

### 3-3. 위험 지수 (현재 구현, 잠정안 — `risk_agent/config.py`)
- 탐지: 요일 중앙값 보정 → 29일 이동중앙값 추세 제거 → MAD robust z(임계 3.5)
- 입력 4개(모두 "클수록 위험"): `baseline_z`(통신 6개월 추세 하락) · `trigger_z`(카드 eval이 baseline보다 낮은 정도) · `event_response`(명절 반응이 동료 코호트보다 약한 정도, H-A) · `micro_signal`(심리상담 키워드율·심각도, 월 5세션 미만이면 null)
- 가중치: 통신 0.20 · 카드 0.30 · 이벤트 0.30 · 미시 0.20 (미시 없으면 0.25/0.375/0.375) — "거시 주, 미시 보정"
- 등급: 분위수 5단계 + 미시 z≥2.0이면 최소 Lv.3
- 원인 분해: 가중치×(부분점수−50) 초과기여. 3점 미만이면 "뚜렷한 원인 없음" → 자원 매칭 대신 "검증 먼저" 제안
- 실제 청년 모드 입력: 카드 `cnt_ex_fixed`(고정지출 제외 건수), 통신 `flow_pop_monthly`

### 3-4. 소셜 월드·안전·개인정보 (구현 기준안, 팀 확정 전)
- NPC 3종(정책추천·취업상담·심리상담)은 **대본형**. 선택지마다 위험 키워드 태그(10종: 무기력·소외감·대화상대없음·장기구직·구직단념·사회적회피·생계부담·고립지속·장기고립·위기발화)와 0~1 심각도. 태그는 UCLA 외로움 척도·De Jong Gierveld·서울시 고립은둔청년 실태조사 문항 주제에서 가져옴.
- **대화 원문 저장 안 함**. `npc_sessions`(본인만 RLS) → DB 함수 `aggregate_npc_sessions()` → `npc_chat_metrics`(코호트×월, user_id 없음, 브라우저 차단) → 에이전트가 secret key로 읽음.
- **k-익명성 k=5**: 미달 코호트는 미시신호 null, 대시보드 키워드 숨김.
- **위기**: 위기 선택지 → 109·1577-0199·112/119 즉시 안내 + `report_crisis()`로 지역·시각·NPC만 `escalations`에 기록(user_id 없음) → 대시보드 상단 알림.
- **환류**: `cohort_feedback`에 코호트별 추천 NPC·미션만. **위험 등급·점수는 시민 화면에 절대 전달하지 않음.**
- 심리상담 NPC는 "상담사가 아니라 스크리닝·연결 도구"로 고지.
- 서비스 대상은 청년(20~30대), **탐지 범위는 전 연령 유지**(고령 신호는 기존 오프라인 돌봄으로 분기).

게임은 팀 DB에, 에이전트는 개인 DB에 붙어서 **에러 없이 순환이 끊긴다.** 또 새 프로젝트는
Authentication → Sign In / Providers → **Anonymous Sign-Ins를 켜야** 게스트 입장이 된다.
팀장의 secret 키를 받아 쓰지 말 것 — 그러면 개인용이 아니라 팀 공용 DB에 쓰게 된다.

#### 0단계 — 최초 한 번만

팀 공용 Supabase를 이미 쓰고 있으면 SQL은 건너뛴다. Supabase 대시보드 → SQL Editor →
New query에 순서대로 붙여넣고 Run. 여러 번 실행해도 안전하다.

```
database/01_socialworld_base.sql     새 프로젝트일 때만
database/02_loop_schema.sql          순환용 테이블 4개 + 함수 2개
database/03_world_update.sql         3D 마을·캐릭터·퀘스트
```

그다음 키를 넣는다.

```bash
cd risk_agent
copy .env.example .env          # Windows 명령 프롬프트(cmd)
cp .env.example .env            # PowerShell · macOS · 리눅스
```

**Windows cmd에서 `cp`를 쓰면 "내부 또는 외부 명령이 아닙니다" 오류가 난다.** cmd는 `copy`다.
탐색기에서 직접 복사해도 되지만, 탐색기는 `.`으로 시작하는 파일 이름을 거부하거나 확장자를
숨겨 `.env.txt`로 저장하는 경우가 있으니 명령어를 권한다.

`SUPABASE_URL`과 `SUPABASE_SECRET_KEY`를 채운다. Project Settings → API Keys →
**Secret keys**의 `sb_secret_...` 값이다. `sb_publishable_...`은 여기서 동작하지 않는다.
**이 키는 커밋·공유 금지.** 브라우저에 들어가는 anon key와 다르다.

```bash
cd data_preprocessing

python run_pipeline.py --check      # 원본 19개 파일 점검
```

`검증 요약: 50/50 항목 일치`가 떠야 정상. `clean/youth_master_daily.csv`가 다음 단계 입력이다.

#### 2단계 — 연결 확인과 배경 데이터 (최초 한 번)

```bash
cd ../risk_agent
pip install pandas numpy
python supabase_sync.py check       # 테이블 4개 ✓ 떠야 다음으로
```

`seed`가 필요한 이유: 시연에서 대화 1~2건만으로는 코호트 집계가 움직이지 않는다.
배경을 깔아두고 그 위에 실제 대화를 얹어야 변화가 보인다.

#### 3단계 — 게임에서 대화 남기기

`social_world/socialworld-demo.html`을 브라우저로 연다. 설치 없이 팀 Supabase에 바로 붙는다.

게스트로 체험하기 → 사전 설문에서 **지역·나이대·성별을 반드시 채운다**(성별을 비우면
코호트가 특정되지 않아 집계에 들어가지 않는다) → 튜토리얼 → 광장 → 심리상담 NPC와 대화.

무거운 선택지로 **3회 정도** — "지치고 힘들어요 → 속얘기할 사람이 별로 없어요 → 몇 달째예요".
로컬 테스트 기준 3건부터 해당 코호트의 환류가 바뀐다. NPC 창을 닫을 때 `npc_sessions`에
1행 저장되고 **대화 원문은 저장되지 않는다.**

```bash
cd risk_agent
```

**이 플래그가 없으면 순환이 끊긴다**(통신·카드만 사용). 출력에 코호트별 세션 수와 쓴 환류가 표시된다.

#### 5단계 — 대시보드 생성

```bash
python build_dashboard.py outputs_youth
```

`outputs_youth/dashboard.html`을 **Chrome 또는 Edge로** 연다.

#### 6단계 — 순환 확인

소셜 월드를 새로고침한다. 세 가지가 보이면 한 바퀴 돈 것이다.

1. 광장의 심리상담 NPC 머리 위 "💬 오늘 이야기 나눠요" 말풍선
2. 미션방에서 추천 미션이 맨 위 + "추천" 배지
3. 대시보드에서 같은 코호트의 '심리상담 신호' 막대 상승

시민 화면에는 위험 등급·점수가 노출되지 않는다. `cohort_feedback`에 등급 컬럼 자체가 없어
구조적으로 막혀 있다.

0·2단계는 끝났으므로 짧아진다.

원본 데이터가 바뀌지 않으면 전처리를 다시 돌릴 필요 없다. 업종 분류나 탐지 임계값만
바꿨다면 `cd data_preprocessing && python run_pipeline.py --only youth` (약 1초).

### 왜 이 순서인가

`run_pipeline.py --youth`의 입력이 전처리 산출물이므로 1단계를 건너뛰면 에이전트가 멈춘다.
반대로 전처리만 하면 위험 등급·추천이 없어 대시보드에 채울 내용이 없다. 4·5단계가 분리된
이유는 에이전트가 CSV·JSON을 만들고 `build_dashboard.py`가 그것을 HTML에 채우는 구조이기 때문이다.
3단계가 4단계보다 앞인 것도 같은 이유 — 대화가 DB에 있어야 에이전트가 그것을 읽는다.

### 단계별 정상 출력

| 단계 | 이것이 나와야 정상 |
|---|---|
| 1 전처리 | `검증 요약: 50/50 항목 일치` · `clean/`에 CSV 12개 |
| 2 연결 | 테이블 4개에 ✓ |
| 4 에이전트 | `[2/10 정합] split 라벨과 1,472행 전부 일치` · `[7/10 우선순위] Lv.3 이상 5개 코호트` |
| 5 대시보드 | `dashboard.html 생성 (46 KB)` |

### 여기서 막힌다 (실제로 겪은 것들)

**대시보드가 빈 화면** → VS Code 미리보기나 탐색기 미리보기 창으로 열었다. JavaScript를
실행하지 않는다. **Chrome이나 Edge로 열어야 한다.**

**`.env` 만들다 오류가 난다** → 대시보드까지만 볼 거라면 `.env`가 필요 없다. 4-A로 가면 된다. 순환까지 해야 한다면 Windows cmd에서는 `cp`가 아니라 `copy .env.example .env`.

**폴더를 못 찾는다** → 전처리 폴더가 `preprocessing`에서 **`data_preprocessing`으로 바뀌었다.**

**에이전트가 입력을 못 찾는다** → `--youth`는 `../data_preprocessing/clean/`을 자동 탐색한다.
위치가 다르면 직접 준다: `python run_pipeline.py --youth <csv 경로>`

**전처리 검증이 50개보다 적게 끝난다** → 구버전 코드다. 41개로 끝나면 청년 단계(7·8)가 없는 버전.

**대화를 3회 했는데 환류가 안 바뀐다** → 사전 설문에서 성별을 비웠거나, `--supabase`를
빼고 돌렸거나, 2단계 `seed`를 하지 않아 배경이 없다.

**캐릭터가 DB에 저장되지 않는다** → 팀 Supabase에 `03_world_update.sql`이 적용되지 않았다.
이때는 기본 정보만 저장되고 캐릭터는 그 브라우저에만 남는다(퀘스트 기록 건너뜀).

### 선택 — 합성 데이터로 탐지 성능 채점

실제 청년 데이터에는 정답 라벨이 없다. 그래서 합성 데이터에 고립 원형을 심어두고 에이전트가
그것을 되찾는지 채점한다. 심사에서 탐지 성능을 보일 때 쓴다.

```bash
cd risk_agent
python run_pipeline.py              # 합성 24코호트 → outputs/
python validate.py                  # 심은 원형 회수 채점 (실패 시 exit 1)
python build_dashboard.py           # outputs/dashboard.html
```

### 참고

`react_app/`은 `npm install && npm run dev`로 돌아가지만 **순환에 아직 연결되지 않았다.**
시연은 단일 HTML 데모로 한다.

위기 선택지("사실 다 그만두고 싶을 때가 있어요")를 고르면 109·1577-0199 안내가 즉시 뜨고
`escalations`에 지역·시각·NPC 종류만 남는다(user_id 없음). 관리자 대시보드 상단 알림에 뜨므로
시연에서 일부러 보여줄 수 있다.

## 6. 알려진 한계 (보고서에 그대로 명시할 것)

- 분위수 등급은 위험이 없어도 상위 20%를 "위험"으로 만든다 → 오탐. 절대 임계값 병행 또는 "두 주기 연속 Lv.3+" 안정성 조건 필요.
- 실제 청년 데이터에서 고립 신호 없음 → **"왜 청년인가"의 데이터 근거가 아직 없다.**
- 거시(2025 하반기)와 미시(현재) 시점 불일치.
- 미시 신호는 시연용(합성 배경으로 k=5 충족). 원형 효과 크기는 가정값.
- 환류가 분위수 등급을 따라 상위 코호트 5/8에 적용됨 — 등급 방식 한계가 개인화로 전파.
- 구조적 한계: 개인 관측 불가(생태학적 오류 주의), 통신 축 교차 불가, 카드 오프라인 한정, 고객 거주지 시도 단위.

## 8. 이어받는 사람(AI 포함)이 지킬 규칙

**코드**
- `DATA/`는 읽기 전용. 통신 로딩의 `drop_duplicates()` 제거 금지(12월 파일 완전중복 → 수치 2배).
- `cohort.build_flow_cohort()`의 "집계 먼저 → melt 나중" 순서 유지(바꾸면 715만 행, 메모리 초과).
- 3분할(`split.add_split_label()`)을 무작위 분할로 바꾸지 말 것(시계열 누수).
- `config.EXPECTED`를 실제값에 맞춰 임의 수정 금지 — 달라진 이유를 먼저 확인·공유.
- `apply(axis=1)` 지양, 통신 3종 동시 로딩 금지.
- 값 조정은 `data_preprocessing/src/config.py`, `risk_agent/config.py`에서만.

**보안**
- Supabase **secret key**는 `risk_agent/.env`에만. 커밋·공유·HTML 삽입 금지. 브라우저에는 publishable key만.
- `.env`, `DATA/`, `clean/`, `outputs*/`는 커밋하지 않는다(`git status`로 확인).
- 관리자 대시보드 HTML은 외부 공개 금지.

**표현(심사 대응)**
- 규칙 기반이므로 **"학습한다" 표현 금지**. "실데이터 축적 시 지도학습 고도화"는 로드맵으로만.
- 실제 청년 데이터의 "위험" 표시를 **고립 발견으로 보고하지 말 것.**
- 합성 검증은 "내적 타당성"으로만 설명.
- 시민 화면에 위험 등급·점수가 노출되는 경로를 만들지 말 것.

**협업**
- `main`은 항상 동작 상태. 짧은 브랜치 + Draft PR. 브랜치 접두사: `data/` `agent/` `world/` `db/` `docs/` `fix/` `chore/` (영어 소문자·하이픈).
