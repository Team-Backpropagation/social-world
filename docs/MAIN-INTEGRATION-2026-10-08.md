# social-world 전체 분석 및 main 통합 결과

분석·작업일: 2026-10-08. 대상: 바탕화면 `social-world` 프로젝트와 `social-world-local-db` 시험 도구.

## 기준 버전과 실제 상태

- 새 main은 정상적으로 내려받아져 있었다. 분석 기준 main은 **4369d96** (`Merge pull request #20 from Team-Backpropagation/shkim`)이다.
- 현재 작업 브랜치는 **min**, 기준 커밋은 **3e77c57** (`1008:탈의실+업적+물고기판매소`)였다. Git 기록에는 main을 pull한 뒤 min으로 돌아온 과정이 있었다.
- 현재 폴더의 추적 파일은 min 내용과 일치했다. Windows CRLF/LF 차이는 내용 변경과 구분했다.
- 공통 기준 **e347231**에서 main 변경과 현재 작업을 비교하여 소스를 통합했다. 새 main만으로 덮어쓸 경우 오늘 만든 옷장·업적·판매점이 빠지므로 양쪽 기능을 보존했다.
- 실행에 필요한 소스·문서·테스트·스키마를 조사했고, 비밀 설정 `.env`, 대회 원자료와 생성 결과는 변경 대상에서 제외했다. Git 커밋·푸시와 실제 팀 DB 적용은 진행하지 않았다.

## 유지되는 게임 기능

- 버스 왕복, 충돌 판정과 승하차 동선, 시장·은행·옷가게 출입.
- 낚시와 온라인 인벤토리, 은행 입출금, 옷 구매·착용, 유저 간 거래 기반.
- 탈의실의 실제 3D 반사 거울과 회전/확대, 집 옷장, 무료 미리보기와 명시적인 구매·착용.
- 낚시 크기/분리수거 업적과 시장 닉네임 위 칭호. 판매하거나 거래해도 원래 달성한 업적 유지.
- 수산 매입소에서 서버 가격으로 물고기를 회수하고 돈을 지급. 요청 복구와 중복 지급 방지.
- 시장 광장·은행·옷가게의 채팅 UI, 창 이동·크기 조절, 캐릭터 얼굴 프로필, 같은 렌더링 프레임의 말풍선 추적.
- main의 하루 정책 안내, 이장/하루 의견 작성, 휴대폰 내 의견함, 운영팀 화면.

**시장 유저 채팅은 계속 페이지 메모리에 있는 UI다.** 사용자 사이의 실시간 전송이나 채팅 DB 저장을 이번에 추가하지 않았다. **내 의견함**은 main의 DB 기반 시민⇄운영팀 대화 기능이다. 두 기능은 저장 방식과 용도가 다르다.

## SQL 적용 순서와 기존 DB

```text
01 기본 → 02 순환 → 03 월드 → 04 코코 → 05 이장
→ 06 하루 → 07 의견함 → 08 경제 → 09 하루 규칙
→ 10 업적 → 11 물고기 판매
```

- 업적 `09_achievements.sql`을 이미 실행했다면 새 `10_achievements.sql`은 같은 스키마의 이름 변경이다.
- 판매 `10_fish_sales.sql`을 이미 실행했다면 새 `11_fish_sales.sql`도 같은 스키마의 이름 변경이다.
- 파일 이름 때문에 잔액·아이템·영수증을 초기화하거나 새 DB로 옮기지 않는다. 재실행 가능한 SQL이지만 이미 적용한 기능을 이름 변경만으로 다시 실행할 필요는 없다.
- 새 main의 06·07·09가 팀 DB에 없으면 관리자가 해당 SQL을 적용한다. 실제 서버의 적용 여부는 관리자가 확인한다.
- 팀 적용 상세는 `database/README.md`와 `FISH-SHOP-DB-GUIDE.md`를 참고한다. 이번 검증은 팀 DB에 데이터를 쓰지 않았다.

## 로컬 시험 도구

`social-world-local-db`는 **DB 버전 4**로 업데이트한다. `STOP-LOCAL-DB.cmd` → `START-LOCAL-DB.cmd`로 재시작하면 기존 버전 1~3에서 필요한 순서대로 올라간다.

- 기존 잔액·예금·아이템·판매 영수증·업적·장착 칭호 유지.
- 하루 정책/개수 조회와 의견 작성·조회·답장·읽음 처리를 로컬 브리지에 추가. 권한 판정은 실제 SQL이 수행한다.
- 새 DB 설치와 버전 3→4 업그레이드·재시작을 검증했다.
- 실제 복지로 정책을 로컬로 자동 수집하지 않는다. 정책 데이터가 비어 있으면 하루는 빈 목록 안내를 보여준다.
- 실제 팀 Supabase SDK·주소를 로컬에서 사용하지 않도록 처리한다. 로컬 데이터 폴더와 현재 실행 중인 서버는 직접 지우거나 종료하지 않았다.
